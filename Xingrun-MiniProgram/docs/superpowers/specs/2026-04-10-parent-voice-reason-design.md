# 家长上传页孩子错因语音整理设计

## 背景

当前家长上传链路已经支持孩子填写错因文本，并由 website 侧进一步生成固定错因分类与备注。

但当前实现存在两个问题：

- 孩子只能手打，不支持直接说出错因
- website 当前固定分类口径不是本轮确认的产品口径

本轮确认后的目标不是继续沿用旧的 6 类固定标签，而是改成新的顶层分类模型，并允许孩子通过语音输入错因。

## 目标

- 支持孩子在家长上传页通过语音表达错因
- 支持孩子继续通过手打方式输入错因
- 无论手打还是语音，最终都走同一条 AI 整理链路
- 顶层分类统一为以下 4 类：
  - 知识点问题
  - 细节问题
  - 方法问题
  - 审题问题
- AI 除了给出顶层分类，还需要生成一段老师可直接阅读的备注
- website 与小程序统一切换到这套新口径，不保留旧 6 类兼容逻辑

## 非目标

- 不要求老师回听孩子原始音频
- 不要求首版保留原始音频地址用于老师端展示
- 不保留旧 6 类固定错因的兼容映射
- 不在首版引入额外的二级枚举分类

## 关键决策

### 1. 输入链路解耦

语音识别与错因整理分成两个独立步骤：

1. ASR 负责把语音转成文本
2. AI 整理负责把文本压缩成老师可读版本，并输出顶层分类与备注

这样做的原因：

- 后续可以独立替换 ASR 供应商，不影响错因分类逻辑
- 语音识别失败和分类失败可以分别重试
- 手打与语音最终都能复用同一套分类接口

### 2. 存储结果以 website 现有字段为主

website 现有库表 `wrong_question_submissions` 已预留相关字段：

- `child_raw_reason_text`
- `primary_error_type`
- `secondary_error_summary`
- `child_reason_input_mode`

首版为了最小迁移，继续复用这几个字段，但重定义业务语义：

- `child_raw_reason_text`：存 AI 整理后的老师可读错因文本
- `primary_error_type`：存新的 4 类顶层分类之一
- `secondary_error_summary`：存 AI 生成备注
- `child_reason_input_mode`：继续标记 `text` 或 `voice`

说明：

- 这里字段名中的 `raw` 与新语义不完全一致，这是一次有意的最小迁移取舍
- 首版不新增老师侧依赖的音频字段

### 3. 顶层分类只保留 4 类

系统只允许以下 4 个顶层值：

- 知识点问题
- 细节问题
- 方法问题
- 审题问题

像 `书写`、`符号`、`单位`、`漏条件`、`辅助线` 这类更细的原因，不再作为主分类枚举，而是进入 AI 备注。

### 4. 老师端不展示工程词汇

虽然后端会存“整理后的错因文本”，但前端不使用“清洗后错因文本”这种工程术语。

老师端展示文案建议使用：

- `孩子错因描述`：对应 `child_raw_reason_text`
- `错因分类`：对应 `primary_error_type`
- `补充备注`：对应 `secondary_error_summary`

页面上不出现：

- `清洗后错因文本`
- `原始转写`
- `ASR`
- `结构化结果`

## 方案对比

### 方案 A：继续沿用旧 6 类分类，只新增语音输入

优点：

- 改动更少

缺点：

- 不符合本轮确认后的产品口径
- 会把旧的细粒度分类继续固化

### 方案 B：新 4 类顶层分类 + AI 备注，复用现有字段名

优点：

- 符合当前产品口径
- 迁移成本低于改库重命名
- 能快速让小程序与 website 统一

缺点：

- `child_raw_reason_text` 字段名与真实语义不完全一致

### 方案 C：新 4 类顶层分类 + 新字段命名 + 全量迁移

优点：

- 数据语义最干净

缺点：

- 需要更多数据库、后端、前端和测试改动
- 首版成本高于当前目标所需

最终采用方案 B。

## 架构设计

### 前端页面状态

家长上传页的错因输入区新增两种入口：

- 手打输入
- 语音输入

建议核心状态结构：

```js
{
  childReasonInputMode: 'text', // text | voice
  childReasonDraftText: '',
  childReasonProcessing: false,
  childReasonClassificationStatus: 'idle', // idle | running | done | failed
  childReasonDisplayText: '',
  childReasonTopLevel: '',
  childReasonNote: '',
  childReasonErrorMessage: ''
}
```

说明：

- `childReasonDraftText` 表示孩子手打内容，或语音转写后的待整理文本
- `childReasonDisplayText` 表示最终提交给 website 的老师可读文本
- 页面只展示最终结果，不展示“原始转写”这种工程层概念

### 前端交互

#### 手打模式

1. 孩子输入错因
2. 点击整理或在提交前自动触发整理
3. 页面展示：
   - 孩子错因描述
   - 错因分类
   - 补充备注
4. 家长确认后提交

#### 语音模式

1. 孩子录音
2. 小程序上传音频到桥接服务
3. 服务端执行 ASR，拿到转写文本
4. 服务端调用错因整理能力，得到：
   - 老师可读错因描述
   - 顶层分类
   - 补充备注
5. 页面展示相同的确认区
6. 家长确认后提交

### 接口设计

#### 1. 语音转写接口

- `POST /wechat/parent/reason-transcriptions`

职责：

- 接收小程序音频文件
- 调用 ASR 服务
- 返回转写文本

返回建议：

```json
{
  "transcriptText": "我把单位换算漏掉了，然后后面也有点写快了"
}
```

说明：

- 该接口只负责转写，不负责分类
- 首版不要求把音频地址持久化到 website

#### 2. 错因整理接口

- `POST /wechat/parent/reason-classifications`

输入：

```json
{
  "childReasonText": "我把单位换算漏掉了，然后后面也有点写快了"
}
```

输出：

```json
{
  "displayText": "单位换算这一步漏掉了，后续计算也因此出错",
  "topLevelReason": "细节问题",
  "note": "主要表现为单位换算遗漏，并带来后续计算偏差"
}
```

约束：

- `topLevelReason` 只能是 4 个固定值之一
- `displayText` 必须是老师可直接阅读的整理文本
- `note` 用于承载细项，不得重复顶层标签名称

#### 3. 最终提交接口

保留现有：

- `POST /wechat/parent/wrong-questions`

但提交参数语义调整为：

```json
{
  "open_id": "...",
  "binding_id": 2,
  "image_url": "https://...",
  "child_reason_input_mode": "voice",
  "child_raw_reason_text": "单位换算这一步漏掉了，后续计算也因此出错",
  "primary_error_type": "细节问题",
  "secondary_error_summary": "主要表现为单位换算遗漏，并带来后续计算偏差"
}
```

说明：

- 当前 bridge 与 website 都需要同步改造，不能再由 website 在提交时内部偷偷沿用旧 6 类 prompt 自动分类
- 更合理的职责是：提交前已经拿到整理结果，提交接口只做落库

### AI 规则

#### 顶层分类规则

AI 只能从以下 4 类中选 1 个：

- 知识点问题
- 细节问题
- 方法问题
- 审题问题

#### 整理文本规则

- 用老师能直接理解的自然中文
- 删除口头禅、重复语、无效停顿
- 保留真正有用的错误信息
- 不使用工程词汇
- 不凭空捏造孩子没有表达过的信息

#### 备注规则

- 备注承载细项，不再单列为固定分类
- 允许出现：单位、符号、书写、漏条件、辅助线、运算顺序等具体表现
- 不要简单复述顶层分类名称

## website 改造范围

### 后端

- 修改 `ai_processor.py` 中错因分类 prompt 和允许值
- 停止沿用旧 6 类固定标签
- 新增或改造转写接口与错因整理接口
- 调整 `/api/wechat/wrong-questions` 的职责边界，使其只负责落库

### 数据层

- 继续复用：
  - `child_raw_reason_text`
  - `primary_error_type`
  - `secondary_error_summary`
  - `child_reason_input_mode`
- 不新增老师端依赖的音频字段

### 前端

- 老师端固定分类选项改成 4 类
- 展示文案改成：
  - `孩子错因描述`
  - `错因分类`
  - `补充备注`
- 清掉旧 6 类相关断言和展示口径

## 失败处理

### 1. 语音上传失败

- 页面提示重新录音
- 不影响已选择的图片和其他已填内容

### 2. ASR 失败

- 提示可重试或切回手打
- 不直接清空当前上传任务

### 3. 错因整理失败

- 保留当前文本输入
- 允许重试整理
- 不静默提交不完整分类结果

### 4. 最终提交失败

- 保留页面上已经确认的错因描述、分类和备注
- 支持原地重试

## 测试要求

- 手打错因 -> 整理成功 -> 提交成功
- 语音错因 -> ASR 成功 -> 整理成功 -> 提交成功
- ASR 失败后切回手打仍可提交
- 整理失败时页面保留当前文本，不丢状态
- website 老师端正确显示：
  - 孩子错因描述
  - 错因分类
  - 补充备注
- website 后端只允许新的 4 类顶层值

## 实施顺序

1. 先改 website 的分类口径与展示口径
2. 再补桥接服务里的语音转写与错因整理接口
3. 最后接入小程序上传页的语音入口与结果确认区

这样做的原因：

- 先把 website 的存储与显示语义定住
- 小程序端后续只对接稳定接口，避免边做边改协议
