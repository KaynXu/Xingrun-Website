# AI+Xingrun 开发计划

## 当前版本判断

当前版本已经完成了产品主链路的第一版：

`家长上传错题 -> AI 初步诊断 -> 学生补填 -> 老师查看错题本 PDF`

所以接下来的开发计划，不再以“把群聊做出来”为目标，而是以“把错题本业务做深”为目标。

## 近期开发目标

## Sprint 1：老师 / 班级表接入

目标：
把目前“老师姓名、班级自由填写”的模式升级为正式映射。

要做的事：
- [ ] 接收老师班级表
- [ ] 设计本地数据结构
- [ ] 小程序首登页改成选择老师 + 选择班级
- [ ] 让学生资料与老师班级绑定
- [ ] 预留后续按老师 / 班级分发数据的能力

产出：
- 稳定的老师 / 班级映射基础层

---

## Sprint 2：历史错题记录

目标：
让每条错题不只存在当天 JSON，而能为后续分析服务。

要做的事：
- [ ] 设计更稳定的记录结构
- [ ] 按学生维度聚合历史错题
- [ ] 允许按老师 / 班级 / 学生查找记录
- [ ] 给后续“重复错”提供历史依据

产出：
- 学生错题历史库

---

## Sprint 3：重复错真实判断

目标：
把“是否重复错”从 AI 推断，改成历史记录驱动。

要做的事：
- [ ] 定义重复错判定规则
- [ ] 基于知识点 / 错误类型 / 时间窗口做匹配
- [ ] 在诊断卡和 PDF 中显示真实重复错标记

建议规则第一版：
- 同一学生
- 同一知识点或相近错误类型
- 在近 7 到 14 天内再次出现

产出：
- 更可信的重复错标签

---

## Sprint 4：老师端汇总优化

目标：
让 PDF 更像“老师工作台导出”，而不是原始记录拼接。

要做的事：
- [ ] 首页增加班级维度统计
- [ ] 增加高频知识点排行
- [ ] 增加高风险学生排行
- [ ] 增加“今日建议先处理什么”
- [ ] 支持按老师 / 班级输出不同 PDF

产出：
- 更可用的老师日报

---

## Sprint 5：定时推题产品化

目标：
让定时推题真正成为老师可用的工具。

要做的事：
- [ ] 做老师端推题入口
- [ ] 选择班级 / 时间 / 题目内容
- [ ] 支持复训题和每日练习题
- [ ] 与历史错题形成闭环

产出：
- 收题 -> 诊断 -> 汇总 -> 推题 的完整链路

## 当前最重要的下一步

你把老师班级表发来之后，项目下一步就很明确：

1. 接老师 / 班级表
2. 改首登页为选择器
3. 建立老师班级学生映射
4. 为按班级输出错题本和定时推题打底
