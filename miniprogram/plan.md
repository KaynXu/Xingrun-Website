# AI+Xingrun 项目计划

## 项目定位

AI+Xingrun 不再是单纯的 “OpenClaw + 微信小程序群聊集成” 项目。

当前更准确的定位是：

`面向数学老师的错题本收集、诊断与跟进助手`

这条产品链路围绕四个角色展开：
- 家长：上传孩子错题图片
- 学生：补填错因、自查卡点
- AI：做初步诊断与整理
- 老师：查看汇总、发现高优先级问题、定时推题

---

## 产品目标

用最小的老师额外操作成本，完成下面这件事：

1. 收集学生错题
2. 自动生成初步诊断
3. 让学生补充“为什么错”
4. 给老师形成可直接查看的错题本汇总
5. 后续支持按班级持续推题和复训

一句话版本：

`帮助数学老师低成本收集学生错题，自动完成初步诊断、学生自查和老师汇总跟进。`

## 新阶段划分

### 阶段 A：稳定收题

目标：
让家长可以稳定、低门槛地把错题交进来。

范围：
- 直达错题本
- 首次登记身份信息
- 图片上传前裁切
- 基础聊天和文件上传

状态：
- 已完成第一版

### 阶段 B：AI 错题诊断

目标：
让系统不只是“收图”，而是能给出老师可读的初步判断。

范围：
- 错误类型
- 知识点识别
- 下一步建议
- 关注等级

状态：
- 已完成第一版

### 阶段 C：学生自查闭环

目标：
让学生对错题做最基本的自我归因，而不是老师单向接收。

范围：
- 学生选择错误类型
- 学生勾选错因
- 学生手动补充说明

状态：
- 已完成第一版

### 阶段 D：老师汇总与查看

目标：
让老师看到的是“可行动的日报”，不是聊天记录。

范围：
- PDF 汇总
- Overview
- 目录页
- 原图详情页
- 学生补填内容

状态：
- 已完成第一版

### 阶段 E：老师 / 班级映射

目标：
把目前前端自由输入的老师和班级，升级为真实映射关系。

范围：
- 老师名单
- 班级名单
- 学生归属正确班级
- 不同班级的路由和数据隔离

状态：
- 下一优先级

### 阶段 F：历史分析与复训

目标：
让系统从“日报工具”升级为“长期错题跟踪工具”。

范围：
- 基于历史记录判断重复错
- 高频知识点统计
- 高风险学生识别
- 定时推题复训

状态：
- 底座已开始，未完成闭环

## 下一阶段优先级

### P0

1. 接入老师 / 班级表
2. 把首登页面改成选择器，不再自由输入
3. 把学生、老师、班级做稳定映射

### P1

1. 用历史数据做真实“重复错”判断
2. 不再只靠 AI 猜测重复错
3. 建立学生维度的错题历史记录

### P2

1. 优化老师 PDF 首页
2. 支持按高关注 / 重复错 / 知识点聚合
3. 增加班级层级汇总

### P3

1. 给老师增加定时推题 UI
2. 不再只保留 HTTP 接口
3. 形成“收题 -> 诊断 -> 汇总 -> 推题”的闭环

- 学生姓名
- 所属老师
- 所属班级
- 上传时间
- 原图
- 错误类型
- 涉及知识点
- 是否重复错
- 建议下一步
- 老师关注等级
- 学生自查错误类型
- 学生自查原因
- 学生补充备注

---

## 当前边界

- OpenClaw 视觉识别依赖当前本地 CLI 与模型配置
- 定时推题当前仍是“房间在线推送”，不是微信订阅消息
- “是否重复错”当前仍有 AI 判断成分，尚未完全由历史记录驱动
- 老师 / 班级映射还没有正式表结构

---

## 当前项目判断

这个项目已经从“技术验证”进入“产品原型”阶段。

接下来不应该再优先做：
- 泛化聊天能力
- 房间系统复杂化
- 无关的 Bot 能力扩展

接下来应该持续围绕：
- 错题上传
- 错题诊断
- 学生补填
- 老师汇总
- 历史跟踪

这五条主线推进。
