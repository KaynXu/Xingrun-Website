# Docs Map

## Markdown 组织原则

这个项目里的 `.md` 不是随手记笔记，而是按用途分层。

- `README.md`: 导航页，只回答“从哪里开始看”
- `*-brief.md`: 一页讲清楚定位、目标、边界
- `*-pilot.md`: 某个试点的范围、流程、验证指标
- `*-template.md`: 可复制执行模板，不混分析结论
- `*-notes.md`: 原始材料、会议摘录、临时观察
- `*-playbook.md` 或 `document-system.md`: 协作规则和操作方法

## 不要混写

- 不要把长期战略和本周进展写在同一文件
- 不要把产品定义和上课素材写在同一文件
- 不要把模板和真实案例写在同一文件
- 不要把已确认结论和随手想法写在同一文件

## 写作建议

- 一个文件只承担一种职责
- 文件名直接体现用途，不追求文艺命名
- 先写结论，再写展开
- 优先让后来者 3 分钟内看懂，而不是一次写很满

## 推荐新增文件的命名方式

- `user-personas.md`
- `success-metrics.md`
- `parent-followup-playbook.md`
- `economics-pilot.md`
- `teacher-input-template.md`
- `weekly-ops-notes.md`
