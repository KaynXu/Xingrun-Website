# 雅思作业批改工作流

本文件用于记录雅思课程家庭作业批改和反馈的固定规则，重点适配雅思写作 Task 1 和 Task 2。

参考样例来自老师已批改的 Word 文档：

- `包同学 模考反馈.docx`
- `刘同学 写作作业 4 批改 全 .docx`
- `段同学 作业反馈 .docx`
- `基础班课作业.docx`

这些样例的批改方式不是单纯给分，而是先判断学生是否真正理解题目和作文逻辑，再用局部修改、评分表、逻辑拆解表和改写版本帮助学生知道下一篇具体改哪里。

## 适用场景

当用户要求批改以下内容时，使用本工作流：

- 雅思大作文 Task 2 家庭作业
- 雅思小作文 Task 1 图表作文
- 模考后的 Task 1 + Task 2 综合反馈
- 基础班多人作文作业集中反馈
- 老师要求“按我的批注逻辑批改”的写作作业

如果作业不是写作，例如阅读、听力或口语，本工作流只能借用“错因归类 + 修改建议”的反馈口吻，不要套用写作四项评分表。

## 核心目标

批改的目标不是把学生文章润色成一篇漂亮范文，而是让学生看懂：

- 当前分数为什么上不去
- 最核心的逻辑问题是什么
- 哪些错误属于必须马上改的致命错误
- 哪些句子只是表达不地道
- 这篇文章按原思路应该怎样重组
- 下一篇作文最先要改哪一个动作

尤其是 Task 2，优先看论点、论据、因果链和 solution 是否解释清楚。不要只做语法润色。

## 固定输入

批改前尽量确认：

- 作业类型：Task 1、Task 2、模考反馈、多人作业反馈。
- 原题题干：Task 2 必须知道是原因解决类、同意不同意类、利弊类还是讨论双方类。
- 学生原文：保留学生原句，不要一上来重写。
- 学生阶段：基础班、目标 5.5、目标 6.5 等。
- 是否需要输出 Word 批改文档。

如果没有题干，先按文章内容推断题型，但必须在反馈里避免过度断言。

## 固定输出结构

### 单篇作文反馈

推荐顺序：

1. 总分或整体判断
2. 四项评分表
3. 总体说明，先解释为什么这么给分
4. 原文局部批改
5. 主要问题拆解
6. 必须改的语法或表达清单
7. 逻辑问题表
8. 基于学生原内容修改后的版本
9. 核心问题和下一步

### 模考反馈

模考同时包含 Task 1 和 Task 2 时，分开批改：

1. `Task 1`
2. Task 1 总分
3. Task 1 四项评分表
4. Task 1 局部批改和改写
5. `Task 2`
6. Task 2 总分
7. Task 2 四项评分表
8. Task 2 致命错误、逻辑表和改写文章

不要把 Task 1 和 Task 2 的问题混在一起。

### 多人作业反馈

多人作业反馈不必给每个人完整四项评分表，可以按学生分块：

- 学生名
- `逻辑问题：`
- 1 到 3 个最关键问题
- 每个问题都给“为什么错”和“怎么改”
- 最后给一篇班级共用范文或结构示范

多人反馈的重点是共性问题，例如论点和论据混在一起、solution 太浅、原因段逻辑跳跃。

## 评分规则

### Task 1

使用四项：

- `TR`
- `CC`
- `LR`
- `GRA`
- `Overall`

常见判断重点：

- `TR`：是否有 overview；overview 是否是宏观信息，而不是把细节提前写进去；数据是否覆盖核心趋势；是否漏掉关键组。
- `CC`：是否按合理标准分组；动态图是否避免按年份流水账；段落内部是否有清晰连接；是否有细节段引入句。
- `LR`：是否反复使用题干词；是否有中式搭配；图表动词是否准确，例如 rise、increase、grow、decline、remain stable、fluctuate、represent、record。
- `GRA`：是否有破碎句、主谓不一致、冠词错误、时态错误、比较结构错误。

Task 1 给分时要特别检查：

- 没有具体时间的图表通常用一般现在时。
- 有明确过去时间区间的动态图通常用过去时。
- overview 写“组”，不写一堆具体年份和数据。
- 细节段按趋势、类别或量级分组，不要按年份拆。
- 数据量级很重要，大数值类别可以单独强调。
- 不要重复描述同一类别，例如同一个 taxi 在两个主体段出现两次。

### Task 2

使用四项：

- `TA`
- `CC`
- `LR`
- `GRA`
- `Overall`

Task 2 是本工作流最重要的部分。

批改优先级：

1. 是否完整回应题目要求。
2. 论点是否清楚。
3. 论点和论据是否分开。
4. 每个主体段是否只讲一个主要机制。
5. 因果链是否直接、可理解。
6. solution 是否解释“为什么能解决问题”。
7. 段落之间和句子之间是否连贯。
8. 词汇和语法是否影响理解。

不要先纠结高级表达。基础学生如果逻辑链断了、句子破碎、solution 没解释，分数会先卡在 4 到 5 分段。

## 作文批改核心逻辑

### 1. 先判断题型和任务完成度

Task 2 必须先看题目问什么。

例如原因解决类：

- 开头段必须说明本文会讨论原因和解决方法。
- 主体段必须分别讲原因和解决方法。
- 结尾段不能缺。
- solution 必须对应前文原因。

如果学生只写了 `growing concern`，却没有提到后文会 propose solutions，要指出这是任务回应不完整。

### 2. 论点和论据必须分开

样例里反复出现的问题是学生把论据塞进论点。

批改时要明确告诉学生：

- 论点就是一句话，告诉读者这个段落主要原因或方案是什么。
- 论据是后面解释、举例和展开。
- 论点不要带半句例子。

推荐反馈句式：

```text
你的论点老喜欢带半句解释，把论据提前塞进论点里了。论点应该就一句，剩下的展开是论据的事。
```

### 3. 一个段落只讲一个主要机制

如果一个原因段里同时出现：

- 学业压力导致没时间运动
- 学业压力导致情绪性进食

要指出这是两个机制，不能硬塞在一个段落里。

可给学生两个改法：

- 拆成两个独立原因。
- 或者把段落主题上收为“学业压力导致生活方式失衡”，再分两层解释。

### 4. 因果链必须直接

低分作文常见问题是因果链太绕或牵强。

例如：

```text
社会发展 -> 选择多 -> 高热量 -> 肥胖
```

可以改成：

```text
快餐随处可见 + 高热量 + 孩子没自制力 -> 体重增加
```

再例如：

```text
经济压力 -> 商人用劣质油 -> 孩子分不清 -> 肥胖
```

这是牵强链条。应建议换成更直接的论点，例如：

- `sedentary lifestyle due to excessive screen time`
- `lack of nutritional education in schools`
- `the availability of fast food has increased dramatically`

### 5. solution 不能停留在“管住”

样例里最重要的 Task 2 批注之一是：解决方案太浅。

如果学生只写：

- 学校每天运动一小时
- 家长控制零食
- 政府管理商家

必须继续追问：

- 为什么这样做能减少肥胖？
- 是减少热量摄入，还是增加热量消耗？
- 是改变习惯，还是减少广告暴露？
- 和前文原因是否对应？

推荐反馈句式：

```text
你的解决方法全是方案，一句都没有解释为什么这样做能解决问题。考官只看到你一味地提出“应该怎么做”，但是不知道这些方法为什么有效。
```

### 6. 低分作文先抓致命语法

对 4 到 5 分段学生，要列出“基础的致命语法/表达错误”。

常见格式：

```text
there have    改成 there are / there were
people is     改成 people are / people were
can choice    改成 can choose / to choose from
must to use   改成 must use
they will facing 改成 they will face
this children 改成 these children
```

这类错误要明确标注：必须改，不改上不了 5 分。

## Task 1 批改重点

### 开头段

先检查 paraphrase 是否准确。

常见问题：

- `messages` 误用成短信信息，应写 `information`。
- `outlet proportion` 误用，应写 `consumer spending` 或 `expenditure`.
- 主语过长，导致读者读到谓语才知道句子在说什么。
- `distinct traffic tools` 这类搭配不自然，应换成 `modes of transport`.

如果主语太长，可以指导学生把修饰语放到主语后面。

### Overview

overview 要写宏观信息，不要写细节数据。

动态图常见 overview：

- 哪些类别总体上升。
- 哪些类别总体下降。
- 哪个类别一直最高或最低。
- 总体趋势是什么。

不要把 5 个活动混在一起逐个说，尤其不要写成“谁快速上升、谁缓慢下降”的细节流水账。

### 细节段

细节段必须有引入句，例如：

```text
Turning to the details, ...
```

分组标准要清楚：

- 按上升/下降分组。
- 按主导类别和其他类别分组。
- 按大幅变化和小幅变化分组。
- 按数据量级分组。

不要按年份写成流水账。动态图不能只写 2005 是转折点、2010 是转折点，然后不断切年份。

### 小作文常见扣分点

- 比较对象不一致，例如 costs 和 countries 直接比较。
- 国家名前乱加 `the`，例如 `the Germany`.
- `among` 和 `between` 混用。
- `create the largest figure` 搭配不当，应改为 `represent / record the highest figure`.
- `every costs` 单复数错误。
- `between 30 to 40` 应为 `between 30 and 40`.
- 同一类别重复出现在两个主体段。
- 过度重复 `distance / travel / activity number`.

## Word 批改格式

如果输出 Word 批改文档，优先沿用老师样例的直接批改方式：

- 不优先使用 Word 边栏 comments；除非用户明确要求。
- 在学生原文中直接保留局部批改。
- 红字或粉红字用于老师即时批注和替换建议。
- 删除线用于删掉多余词或错误词。
- 下划线用于标出需要学生注意的关键表达。
- 加粗用于强调必须改的错误或修改后的关键词。
- 蓝色可用于“核心问题”标题、范文里的 topic sentence 或关键逻辑句。
- 表格用于评分和逻辑拆解。

不要把整篇学生作文全部删掉重写。必须让学生能看见“自己的原句 -> 问题 -> 应该怎么改”。

## 固定反馈语气

语气要像老师本人在给学生讲，不像系统报告。

可以使用：

- “你可以看看”
- “这个地方会被扣很多分”
- “我读得有点懵”
- “这里其实是两个方向”
- “这个咋能忘记”
- “不改上不了 5 分”
- “你下次先记住这个动作”

但每一句情绪化提醒后面都必须跟具体原因或修改方法。不要只骂，不给路。

## 改写版本规则

改写分两种。

### 基于学生内容修改

这是默认改写方式。

要求：

- 尽量保留学生原本想表达的内容。
- 修正逻辑链和段落结构。
- 替换明显中式表达。
- 补足缺失的解释句。
- 不要突然写成学生看不懂的高阶范文。

样例口径：

```text
这是我基于你的内容改正的，你可以看看，主要是改了逻辑。
```

### 高分范文

只有在用户要求或学生程度足够时再给。

要求：

- 先给段落逻辑说明，再给正文。
- 标出段落的功能，例如下降组、上升组、原因 1、原因 2、解决 1、解决 2。
- 不要只丢一篇范文给学生背。

## 作文 proof 要求

每次沉淀新批改工作流或生成批改文档后，必须用临时脚本 proof。

至少检查：

- 读取到的 docx 数量。
- 是否能提取正文文本。
- 是否能识别表格。
- 是否能识别红字、蓝字、加粗、删除线、下划线等格式线索。
- 工作流文档是否包含 Task 1、Task 2、评分表、逻辑问题、致命语法、改写版本和 Word 格式规则。
- `git diff --check` 通过。

如果生成的是 Word 批改文档，还必须渲染检查页面，不要只看文字提取。

## 最终交付说明

交付时说明：

- 新工作流文件路径。
- 参考了哪几个 Word 样例。
- 是否特别覆盖了作文 Task 2。
- proof 是否通过。
- 如果只是生成工作流，不要把 4 个 Word 原件提交进仓库。
