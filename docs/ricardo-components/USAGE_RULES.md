# Ricardo 组件库使用章程

这个章程用于约束 Ricardo 组件库的使用方式，尤其适用于只会用 AI 写代码的人。目标是让每次调用组件都有固定口径，不靠临时描述和自由发挥。

## 核心原则

1. 先调用已有组件，再考虑新做组件。
2. 调用组件前必须填写必要信息。
3. 不允许只说“做一个类似的”。
4. 不允许为了一个页面随意改坏组件的通用行为。
5. 如果需求和组件原定义冲突，先更新组件文档，再改代码。
6. 如果只是继续治理路线，先确认是否真的进入组件代码修改；没有确认时只补文档和对齐口径。

## 调用组件时必须说明

调用 Ricardo 组件库里的组件时，至少说明：

- 组件编号。
- 中文名或英文名。
- 使用页面。
- 入口文字。
- 层级数量。
- 每层内容。
- 选项来源。
- 是否支持 hover。
- 是否支持点击。
- 选择后是否关闭浮层。
- 是否有权限差异。
- 是否有额外搜索框。
- 是否有禁改点。

## 最简单调用口令

如果 Ricardo 记不住组件名字，可以直接复制下面这句话：

```text
调用 Ricardo 组件库 RCF-001，用在【页面名】页面，入口文字是【入口文字】，筛选层级是【层级数量】，每层内容是【每层内容】。先复述需求和风险，不要直接做。
```

```text
调用 Ricardo 组件库 RCF-002，用在【页面名】页面，入口文字是【入口文字】，筛选层级是【层级数量】，每层内容是【每层内容】。先复述需求和风险，不要直接做。
```

如果不确定该用哪个组件，可以这样说：

```text
我要做一个筛选，请先判断应该调用 Ricardo 组件库里的哪个组件。先复述你的判断，不要直接做。
```

## 当前筛选组件

### RCF-001：浮层标签筛选器

英文名：Floating Label Filter

适用：

- 班级管理。
- 学员管理。
- 多条件列表筛选。

默认口径：

- 第一层是一排标签。
- hover 或点击标签后，下方出现选项框。
- 选择后标签显示已选内容。
- 已选标签带 `x`，点击后恢复默认。
- 多个标签可以逐步缩小范围。
- 标签可以配置左侧图标。
- 可以隐藏右侧范围标签和底部说明，让卡片更紧凑。
- 可以启用悬浮选项框，不占页面高度；用于课程日历时，要保留 80ms 短延迟关闭，避免鼠标移向下一层时误关。

禁改点：

- 不要在选项里加入“全部学科”“全部教师”这类全部选项。取消筛选用标签上的 `x`。
- 额外搜索框不算筛选标签，例如 `学员姓名查询`。
- 电脑端可以 hover，Pad 和手机端必须 click 可用。

### RCF-002：总览浮层筛选器

英文名：Overview Floating Filter

适用：

- 校区总览。
- 标题旁边的轻量范围筛选。

默认口径：

- 入口是短标签，例如 `全校区`。
- 点击或 hover 入口后出现第一层。
- hover 或点击第一层后，在下方出现第二层。
- 选中后入口显示筛选摘要。
- 入口带 `x` 可一键清空。

禁改点：

- 第二层放在第一层下方，不放右侧，避免误触。
- 未 hover 或点击前，不提前展示第二层。
- 再次点击已打开的第一层标签时，第二层关闭。

## 新组件入库规则

新组件入库时，必须补齐：

- 编号。
- 中文名。
- 英文名。
- 使用效果。
- 适用场景。
- 调用前必须确认的问题。
- 禁改点。
- 已使用页面。
- 版本记录。

并在 `docs/ricardo-components/README.md` 中登记。

## 页面需求对齐提醒

每次修改一个页面前，先检查：

- Ricardo 是否明确同意开始改这个页面。
- 这个页面是否有权限差异。
- 是否涉及班级命名。
- 如果涉及当前正式班级名，是否应接入命名规则 1。
- 是否属于历史快照、手动文本、旧备注、别名匹配、小程序/家长端兼容展示等命名规则 2 范围；如果是，先不要改。
- 是否涉及筛选逻辑。
- 是否能调用 Ricardo 已有组件。
- 是否需要新增组件入库。
- 是否需要更新技术债账本。
- 是否需要新增规则测试。

如果涉及权限差异，先定义权限判断层，再做展示层。
如果涉及班级名，默认口径是：页面展示层只显示年级和班级；权限判断层可打开“入学年份”。
