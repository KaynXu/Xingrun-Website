# 智能错题错题复习 PDF 生成工作流

本文件用于记录“智能错题”里按学生或班级生成错题复习 PDF 的固定工作流。

它和 `review-plan-workflow.md` 不同：`review-plan-workflow.md` 面向课堂录音、课堂反馈和整节课课后复习计划；本文件面向已经进入智能错题库的学生错题，目标是把指定日期范围内的错题整理成可直接发给学生重做的错题复习 PDF。

参考样例：

- `output/pdf/陈采薪-李迎萌-周一周二错题复习PDF-20260525-20260526 3/小姝老师小课-陈采薪-周一周二错题复习-20260525-20260526.pdf`

## 适用场景

当用户提出以下类似需求时，使用本工作流：

- 调取某个学生最近几天的错题，生成错题复习 PDF。
- 调取某个班级某个周末或某几天的错题，按学生分别生成 PDF，再打包 zip。
- 把智能错题中的原题、原图、错因和老师修正方向整理成“错题复习”。

不要把本工作流用于课堂录音生成的间隔复习计划；那类任务继续使用 `review-plan-workflow.md`。

## 固定输入

每次开始生成前，先明确这些信息：

- 学生范围：单个学生、多个学生，或某个班级。
- 日期范围：使用精确起止日期，按左闭右开区间查询，例如 `2026-05-25 00:00:00` 到 `2026-05-27 00:00:00`。
- 错题状态：只使用 `recognized + active` 的错题。
- 数据来源：优先使用本地/生产库里的微信小程序错题 `wechat_mp` 记录。
- 输出口径：每个学生 1 份 PDF；多人或整班生成时再打包 1 个 zip。

如果用户使用“周一周二”“上周末”“今天”这类相对说法，必须先换算成具体日期，并在最终说明里写清楚。

## 数据核对

生成前必须做一次题量核对：

1. 按学生、班级和日期范围查询候选错题。
2. 只保留识别成功、未归档、未删除的有效错题。
3. 按学生分组，记录每个学生的题量。
4. 按日期分组，确认标题中的“周一/周二/周末”等描述和实际题目日期一致。
5. 如果某天没有错题，不要在封面范围里写入这个空日期。

最终 PDF 的封面题量、每日题量和 proof 查询题量必须一致。

## 固定输出

输出目录命名：

```text
output/pdf/<学生或班级范围>-<日期描述>错题复习PDF-YYYYMMDD-YYYYMMDD/
```

单个 PDF 命名：

```text
<班级或课程名>-<学生姓名>-<日期描述>错题复习-YYYYMMDD-YYYYMMDD.pdf
```

多人或整班输出时，同时生成 zip：

```text
output/pdf/<学生或班级范围>-<日期描述>错题复习PDF-YYYYMMDD-YYYYMMDD.zip
```

生成新批次时可以保留历史输出；不要误删旧 PDF 或旧 zip。

## PDF 固定结构

每份 PDF 使用以下结构：

1. 封面和说明页
2. 每道错题 1 个独立题块，优先 1 题 1 页
3. 每题固定顺序：
   - `原题 / 原图`
   - `方法提醒`
   - `挖空复盘`
   - `订正区`

### 封面页

封面必须包含：

- 标题：`<班级或课程名> <学生姓名> <日期描述>错题复习`
- 范围：写明具体日期，例如 `周一 2026-05-25、周二 2026-05-26`
- 老师姓名
- 可复习错题总数
- 使用说明
- 本次错题概况
- 错因分布
- 复习重点
- 每日题量说明

封面不要写空日期，也不要把无题日期放进范围说明。

### 单题页标题

每道题的页内标题固定为：

```text
<日期描述>｜YYYY-MM-DD 错题 N｜<错因类型>｜记录 <record_id>
```

错因类型优先使用 `primary_error_type`，没有时再使用可读的回退文案。

### 原题 / 原图

这一块是学生复盘的起点，优先展示原图：

- 原图必须保持比例，不得拉伸变形。
- 原图不要裁掉题干、图形、学生圈画和老师批注。
- 如果原图过高，按最大高度等比缩放，必要时让这一题自然跨页。
- 如果没有可用原图，展示 `question_text`。
- 如果原图和题干文本都可用，优先保留原图；题干文字可作为辅助摘要。

### 方法提醒

方法提醒是老师给学生的轻提示，不是完整答案。

固定写法：

- 2 到 3 条短句。
- 第一条给通用解题路径。
- 第二条结合本题错因，写“本题重点修正：...”。
- 第三条提醒订正动作，例如重新抄条件、补步骤、检查单位或检验答案。

不要在方法提醒里直接把题目完整解完。

### 挖空复盘

挖空复盘用于让学生补回方法和错因。

固定要求：

- 至少包含一个主题小节，例如 `【方法应用】`、`【知识辨析】`、`【审题定位】`、`【细节检查】`。
- 每题保留 2 到 4 个关键空。
- 空格使用较长下划线，保证学生有书写位置。
- 结尾固定保留：
  - `我这题真正错在：________________`
  - `下次看到同类题，我先做：________________`

挖空内容必须围绕题目真实错因，不要写和题目无关的泛泛鸡汤。

### 订正区

订正区必须是独立书写区域，不能只放一个标题。

排版要求：

- 订正区放在挖空复盘下方。
- 使用浅灰或边框书写框。
- 高度要足够学生完整重做原题。
- 标题不能压到挖空复盘框内。
- 不要让订正区与页脚、下一题标题或原图重叠。

如果页面空间不足，优先把订正区整体移到下一页，不能压缩到不可写。

## 排版硬规则

这是本工作流最重要的部分。

- 题目块顺序固定为 `原题 / 原图 -> 方法提醒 -> 挖空复盘 -> 订正区`。
- 每道题尽量独立成页；如果跨页，必须在自然分隔处换页。
- 原图、挖空复盘、订正区都不能互相重叠。
- 题目标题、section 标题和正文之间要有稳定间距。
- 页眉可以显示 PDF 标题，页脚可以显示页码。
- 同一学生 PDF 内的字号、边距、卡片样式要保持一致。
- 不要把过长题干压成很小字号；宁可分页。
- 不要让中文、数字、公式或下划线挤出页面边界。

生成后必须抽查首尾页和至少 1 页中间题页；如果发现空白页、重叠、标题压框、原图裁切，必须重排后再交付。

## LaTeX 和公式处理

智能错题里的题干可能来自 AI 识别，常见问题是 LaTeX 被 JSON 转义或纯文本 PDF 吞坏。生成 PDF 前必须先做公式清洗。

固定要求：

- 最终 PDF 中不要直接显示 `$...$` 分隔符。
- 不要出现残缺片段，例如 `rac`、`ext`、`mathbbR`、`ldots`。
- 修复 JSON 转义吞掉的公式命令，例如 `\text`、`\to`、`\frac`、`\neq` 被错误变成控制字符的情况。
- 处理未包 `$...$` 的裸公式片段，例如 `\in`、`\mathbb{R}`、`\ldots`、`\frac{a}{b}`、`^{...}`。
- 如果当前生成链路是 ReportLab 纯文本输出，先把 LaTeX 转成可读数学文本，例如把分式转成 `(分子)/(分母)`。
- 如果当前生成链路是浏览器/KaTeX 输出，必须确认公式已经渲染成可见数学内容，而不是把原始 LaTeX 暴露给学生。
- 对几何题、坐标题、函数题和方程题尤其要检查公式、角标、分式、根号、集合符号和坐标括号。

proof 里必须统计：

- PDF 全文 raw `$` 数量。
- 常见坏片段数量：`rac`、`mathbbR`、`ldots`、裸 `\frac`。

这些数量应为 0；如非 0，必须说明原因并修复。

## 内容生成原则

错题复习 PDF 不是答案册，目标是让学生重新经历正确方法。

每题内容应来自这些字段或信息：

- 原题文本和原图
- 学生自述错因
- 老师修正后的错因类型
- 二级错因摘要
- 题目所属知识点或专题
- 是否几何题、是否需要保留图形

生成内容时遵守：

- 方法提醒只提示路径，不直接替学生完成订正。
- 挖空复盘优先围绕本题错因，不扩大到无关知识点。
- 审题类错题重点写“圈条件、找问法、单位和限制条件”。
- 方法类错题重点写“先选方法路径，再列步骤”。
- 知识点类错题重点写“定义、公式、性质、适用条件”。
- 细节类错题重点写“符号、单位、计算、抄写、检验”。
- 几何题必须提醒补标条件、角关系、辅助线或定理来源。

## 验证要求

每次生成后必须用临时脚本 proof，不要只说“应该没问题”。

proof 至少包含：

- 生产库或本地库查询题量。
- 每个学生的题量。
- 输出 PDF 数量。
- zip 内 PDF 数量。
- PDF 页数和文件大小。
- PDF 文本中 `原题 / 原图`、`方法提醒`、`挖空复盘`、`订正区` 的出现次数。
- 每个题页 section 顺序是否正确。
- raw `$` 和常见坏 LaTeX 片段数量。
- 首页、末页和至少一页中间题页渲染非空。
- 对非 PDF/ZIP 代码或文档改动运行 `git diff --check`。

proof 输出必须回传给用户，尤其是题量、页数、公式检查和渲染检查结果。

## 最终交付说明

回复用户时只说关键结果：

- 是否生成成功。
- 日期范围。
- 每个学生题量。
- PDF 目录和 zip 路径。
- proof 是否通过。
- 如果有残留风险，例如某道原图较糊、某题公式来自 AI 识别需老师复核，要明确指出。

不要把 `master` 合并或发布动作混入本工作流。生成错题复习 PDF 只到本地输出或用户指定交付位置为止。
