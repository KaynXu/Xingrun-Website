# 每日错题练习包企业微信自动发送工作流

本文件用于 Codex 自动化每天定时生成错题练习包，并发送到企业微信群 `错题发送`。

它和 `wrong-question-review-workflow.md` 的关系：

- `wrong-question-review-workflow.md` 是手动工作流，适合用户指定学生、班级或日期范围后生成错题复习 PDF。
- 本文件是自动化工作流，适合每天固定时间全量扫描老师、班级和学生，生成老师维度 zip，并通过企业微信发送。

自动化必须以本文件为准。历史 practice pack/API 设计文档已废弃并从仓库移除；自动化不得退回旧的网页 API、七天排期或答案页练习包口径。

## 适用场景

当用户要求 Codex 自动化执行以下任务时，使用本工作流：

- 每天固定时间从本地后端数据里找学生可练错题。
- 每个学生单独计算本次练习方向。
- 每位老师生成 1 个独立 zip。
- zip 内按班级分文件夹，班级文件夹内放学生 PDF。
- 通过本机已登录企业微信，把每位老师的 zip 单独发到 `错题发送` 群。

不要把本工作流用于课堂录音课后复习计划；那类任务继续使用 `review_plan_templates/review-plan-workflow.md`。

不要把本工作流用于人工指定日期范围的临时交付；那类任务继续使用 `docs/wrong-questions/wrong-question-review-workflow.md`。

## 自动化固定设置

- 运行时间：中国时间每天 `14:00`，周末也运行。
- 运行目录：`/Users/xiaodi/Desktop/xingrun.web`。
- 数据来源：本地项目 SQLite 和后端数据层。
- 发送目标：企业微信群 `错题发送`。
- 发送方式：使用 Computer Use 操作本机已登录企业微信。
- 授权状态：用户已授权自动化在计划运行时直接发送本任务生成的错题练习 zip/PDF 到 `错题发送` 群，不需要再向用户确认。

如果群名不是 `错题发送`，或发送对象、文件内容、数据范围发生变化，必须停止并报告，不要猜测发送。

## 数据来源

自动化不要调用网页 HTTP API，不依赖 Flask 路由、前端页面、浏览器登录态或网页 token。

优先直接使用：

- `lesson_manager.py`
- `pdf_engine.py`
- 本地 `data/xingrun.db`
- 现有错题候选、PDF 渲染和公式清洗能力

候选错题必须满足：

- `source='wechat_mp'`
- `recognition_status='recognized'`
- `archive_status='active'`
- 学生仍属于该班级
- 班级仍绑定到对应老师

如果 DeepSeek、OpenAI 或其它 AI key 缺失，自动化不能因此整体失败。没有 AI 时，使用错题记录字段生成确定性内容。

## 老师和班级范围

自动化按老师维度聚合：

1. 查询所有绑定了班级的老师。
2. 找到老师名下所有班级。
3. 找到每个班级里有可练错题的学生。
4. 每位老师生成 1 个 zip。
5. 每位老师单独发送 1 条企业微信消息。

如果某位老师没有可练错题：

- 不生成空 zip。
- 仍发送一条简短说明到 `错题发送` 群。
- 说明里写清老师姓名、生成日期和“今日暂无可生成错题练习”。

## 学生级练习方向

每个学生单独计算练习方向，不允许用全班或全校统一方向强行覆盖。

方向分两类：

- `topic`：按知识点、专题或 `topic_category` 练习。
- `reason`：按错因、错误类型或错因摘要练习。

轮换规则：

1. 每个学生一周内优先练同一类方向。
2. 下周优先切换到另一类方向。
3. 如果切换后的方向没有候选题，可以回退到该学生仍有题的方向。
4. 方向选择优先使用该学生自己的错题分布和最近练习记录。
5. 同分时，优先选择最近更久没练过、未掌握题更多、易反复错题更多的方向。

示例：

- 本周某学生练 `topic: 计算`。
- 下周优先练 `reason: 计算错因`、`reason: 审题遗漏` 或该学生最集中的错因。
- 如果该学生只有计算类错题，允许继续练计算，但要在生成说明里写明回退原因。

## 选题规则

真实历史错题优先。每个学生优先使用自己的真实错题，不要跨学生借题。

推荐题量：

- 默认轻量：每个学生 1 到 5 题。
- 如果学生可练错题不足，按实际题量生成。
- 不要为了凑数引入不相关错题。

如果允许 AI 补题：

- 只能生成同方向、同错因或同知识点变式。
- 必须基于该学生的真实错题。
- 不能跨错因、跨知识点补题。
- 生成后要做审稿检查。

如果不使用 AI：

- 不生成变式题。
- 用真实错题生成确定性 PDF。
- 内容从题目、原图、错因、知识点字段中整理。

## PDF 内容结构

学生文件必须是 PDF。

每份 PDF 继续遵守 `wrong-question-review-workflow.md` 的错题复习结构：

1. 封面和说明页
2. 每道错题 1 个独立题块
3. 每题固定顺序：
   - `原题 / 原图`
   - `方法提醒`
   - `挖空复盘`
   - `订正区`

自动化不能退回成旧版“只排一周任务和答案页”的练习包格式。即使使用现有 practice pack 代码，也必须保证学生看到的是错题复习工作流里的四段结构。

### 方法提醒

方法提醒只提示路径，不直接给完整答案。

固定要求：

- 2 到 3 条短句，直接分行写，不使用项目符号、圆点、编号或其它 bullet。
- 如果本次学生方向是 `topic`，每条都要落到该学生本次具体知识点、专题或 `topic_category`，不要只写“复习知识点”。
- 如果本次学生方向是 `reason`，每条都要落到该学生本次具体错因、`secondary_error_summary` 或孩子自述错因，不能只写“计算错因”“方法问题”。
- 第一条给本题入口动作，例如先列关系、先分类讨论、先圈单位、先标条件。
- 第二条点名具体修正对象，但不要写成“本题重点修正：...”这种统一模板。
- 第三条提醒订正动作，必须是可执行动作，例如补全分类、重列等量关系、逐项检查符号或单位；不要写“订正时先补全”“这一步”“重新写完整过程并检查答案范围”这类套话。
- 文本要像老师手写给学生的一两句短提醒，自然、有逻辑、少废话；不要出现“AI”“模型”“生成”“分析如下”等 AI 套话。

示例：

```text
先利用非负数和为 0，分别令每一项等于 0。
面积含绝对值时，点 P 在线的左右两侧都要考虑。
把 △AOP 的面积写成 |x|，再和四边形面积的两倍比较。
```

### 挖空复盘

挖空复盘必须围绕真实错因。

固定要求：

- 至少有一个具体主题小节，例如 `【相遇关系辨析】`、`【分类讨论补全】`、`【去分母检查】`、`【单位换算检查】`。
- 如果练 `topic`，填空句必须点名本次知识点的关键规则、条件或适用范围。
- 如果练 `reason`，填空句必须点名本次错因的具体表现和下次检查动作。
- 每题 2 到 4 个关键空，空格放在具体关系、条件、单位、范围、步骤或分类上。
- 结尾固定保留：

```text
我这题真正错在：________________
下次看到同类题，我先做：________________
```

如果没有 AI，挖空内容可以由模板生成，但必须引用本题知识点、错因或孩子自述内容，不要写空泛话。

反例：

```text
【知识解析】本题关联某个知识点，我先写出关键规则：________。
```

这类句子太空，不能使用。

选择题题干如果识别成一整行，必须先把选项拆行，例如 `A.6 B.7 C.8 D.9` 要排成 `A. 6`、`B. 7`、`C. 8`、`D. 9` 分行展示，不能挤在题干同一行。

### 订正区

订正区必须是独立书写区域，不能只有标题。

如果页面空间不足，优先把订正区整体移到下一页，不能压缩到不可写。

## Zip 输出结构

输出目录建议：

```text
output/pdf/每日错题发送-YYYYMMDD/
```

每位老师一个 zip：

```text
output/pdf/每日错题发送-YYYYMMDD/<老师名>-错题练习包-YYYYMMDD.zip
```

zip 内结构：

```text
<老师名>-错题练习包-YYYYMMDD.zip
├── <班级名>/
│   ├── <班级名>-<学生名>-<练习方向>错题练习-YYYYMMDD.pdf
│   └── ...
├── <另一个班级名>/
│   └── ...
└── 生成说明.txt
```

文件名必须包含：

- 班级名
- 学生名
- 本次练习方向
- 生成日期

`生成说明.txt` 必须包含：

- 老师姓名
- 生成日期
- 本周轮换模式
- 班级列表
- 每个学生的练习方向
- 每个学生题量
- 跳过或回退原因

生成新批次时可以保留历史输出，不要误删旧 PDF 或旧 zip。

## 企业微信发送

发送前必须确认：

- 企业微信正在运行或可启动。
- 当前群聊是 `错题发送`，或能明确搜索并打开 `错题发送`。
- 待发送文件是本次生成的老师 zip。
- zip 内 PDF 数和 proof 汇总一致。

每位老师发送一条消息，消息正文包含：

- 老师姓名
- 生成日期
- 包含班级
- 学生 PDF 数量
- 本次练习方向规则
- zip 文件名

消息正文示例：

```text
平台管理员 2026-06-02 错题练习包已生成。
班级：七年级5班-本周错题测试
学生PDF：4份
本周规则：按学生个人错题分布练 reason 方向；下周优先切换 topic 方向。
文件：平台管理员-错题练习包-20260602.zip
```

随后附上该老师 zip。

如果发送失败：

- 不要删除本地 zip。
- 报告失败步骤。
- 报告本地 zip 路径。
- 如果已经发送了部分老师，列出已发送和未发送名单。

## LaTeX 和公式处理

继续遵守 `wrong-question-review-workflow.md` 的公式规则。

proof 里必须统计：

- raw `$`
- `rac`
- `mathbbR`
- `ldots`
- 裸 `\frac`

这些数量应为 0。如非 0，必须先修复再发送。

## Proof 要求

每次自动化必须运行临时 proof 脚本。

proof 至少输出：

- 数据库路径。
- 候选错题总数。
- 每位老师的班级数、学生数、PDF 数。
- 每个学生的方向、题量和 PDF 路径。
- 每位老师 zip 路径和大小。
- zip 内 PDF 数量。
- zip 是否包含班级文件夹。
- zip 是否包含 `生成说明.txt`。
- 每份 PDF 页数和文件大小。
- 每份 PDF 常见坏 LaTeX token 计数。
- 首页、末页和至少一页中间页渲染非空。
- 企业微信发送状态。

proof 输出必须回传。不要只说“已完成”。

## 自动化最终回报

最终回报按结果优先：

- 是否生成成功。
- 是否发送成功。
- 每位老师 zip 路径。
- 每位老师发送状态。
- 跳过学生或老师的原因。
- proof 是否通过。

不要在本工作流里执行 `master` 合并、发布或生产部署。
