# 机构申请与邀请码加入设计

## 背景

当前系统的注册流程默认把所有新账号都归属到 `星润Starain`。数据库底层已经具备多机构能力，但公开注册入口和前端表单仍然把机构写死，导致其他机构无法独立开通和管理自己的空间。

这次目标是把单一机构注册流程升级为：

- 新机构先提交“机构开通申请”
- `Kayn` 作为全局 `super_owner` 统一审批机构申请
- 审批通过后，申请人自动成为该机构的首个 `owner`
- 机构成员后续不再手填机构名，而是通过“邀请码”或“Web 邀请链接”加入对应机构
- 每个机构同一时间只允许一个有效的邀请码/邀请链接
- 机构 `owner` 可以随时重置邀请码和邀请链接，旧入口立即失效

## 目标

- 支持多机构独立开通，而不是默认归属 `星润Starain`
- 保持现有 `organizations` 与 `users.organization_id` 的机构归属模型
- 让成员加入机构的路径简化为“验邀请码/验邀请链接后直接注册”
- 把邀请能力设计成独立数据模型，为后续扩展保留空间

## 方案概览

采用“两段式机构体系”：

1. 机构开通走全局审批流
2. 成员加入走机构邀请流

系统新增两个核心实体：

- `organization_requests`
  - 记录待审批的机构开通申请
- `organization_invites`
  - 记录机构邀请码与邀请链接
  - 当前业务规则仅允许每个机构存在一条 `active` 邀请

现有 `organizations`、`users` 继续复用，不做破坏性迁移。

## 角色与权限

- `super_owner`
  - 全局最高权限，当前固定为 `Kayn`
  - 负责审批机构开通申请
- `owner`
  - 某个机构的管理者
  - 审批通过的机构申请人自动成为本机构首个 `owner`
  - 负责查看和重置本机构的邀请码/邀请链接
- `admin` / `member`
  - 保持现有含义
  - 不参与机构创建与邀请重置

权限边界：

- 只有 `Kayn` 可以审批机构申请
- 普通机构 `owner` 不能创建新机构
- 只有机构自己的 `owner` 可以读取和重置本机构邀请
- 成员通过邀请码或邀请链接加入时，不再走全局人工审批

## 核心流程

### 1. 申请开通机构

未登录访客可在公开页进入“申请开通机构”流程，提交：

- 机构名称
- 申请人用户名
- 申请人显示名
- 密码
- 确认密码

提交成功后：

- 创建一条 `organization_requests.status = pending`
- 等待 `Kayn` 在后台审批

约束：

- 机构名称不能与现有机构重名
- 机构名称不能与待审批机构申请重名
- 申请人用户名不能与现有账号重复
- 申请人用户名不能与待审批机构申请或待审批成员申请重复

### 2. 审批机构申请

`Kayn` 在后台查看机构申请队列，支持“通过 / 拒绝”。

通过时：

- 创建 `organizations` 记录
- 创建申请人账号，角色为该机构首个 `owner`
- 自动生成一条 `organization_invites.status = active`
- 机构申请状态改为 `approved`

拒绝时：

- 机构申请状态改为 `rejected`
- 不创建机构，不创建用户

### 3. 邀请加入机构

成员加入已有机构支持两种方式：

- 手动输入邀请码
- 访问 Web 邀请链接

两种入口最终都落到同一个机构邀请校验逻辑：

- 邀请码或 token 存在
- 对应邀请状态为 `active`
- 对应机构仍然存在

校验通过后，用户提交：

- 用户名
- 显示名
- 密码
- 确认密码

然后系统直接创建正式账号并归属到目标机构，账号状态为 `active`。

这里明确采用“验码即加入”的规则，不追加第二层人工审批，否则会与邀请码/邀请链接的加入模型冲突。

### 4. 重置邀请码/邀请链接

机构 `owner` 可以在后台执行“重置邀请入口”。

重置时：

- 当前 `active` 邀请改为 `revoked`
- 新建一条新的 `active` 邀请
- 新邀请码和新邀请链接立即生效
- 所有旧邀请码和旧链接立即失效

## 数据设计

### `organization_requests`

建议字段：

- `id`
- `organization_name`
- `username`
- `password_hash`
- `display_name`
- `status`
- `reviewed_by`
- `reviewed_at`
- `created_at`

状态：

- `pending`
- `approved`
- `rejected`

说明：

- 这张表只承载“机构开通申请”
- 不替代现有成员注册申请表；若后续成员改为全量邀请码加入，可以再评估是否弱化旧表用途

### `organization_invites`

建议字段：

- `id`
- `organization_id`
- `invite_code`
- `invite_token`
- `status`
- `created_by`
- `revoked_at`
- `created_at`

状态：

- `active`
- `revoked`

规则：

- 每个机构任意时刻最多一条 `active`
- 历史记录保留在表内，便于后续审计或扩展

### 现有数据复用

- `organizations`
  - 继续作为机构主表
- `users.organization_id`
  - 继续作为账号机构归属来源
- 现有 `registration_requests`
  - 本次不删除，但公开成员注册入口将逐步被“邀请码加入”替代

## API 设计

### 机构申请

- `POST /api/organization-requests`
  - 提交机构开通申请

### 机构申请审批

- `GET /api/admin/organization-requests`
  - 获取待审批机构申请列表，仅 `Kayn` 可用
- `POST /api/admin/organization-requests/<id>/approve`
  - 审批通过
- `POST /api/admin/organization-requests/<id>/reject`
  - 审批拒绝

### 邀请加入

- `GET /api/invite/<token>`
  - 读取邀请链接对应的机构信息，用于公开页预填目标机构
- `POST /api/join-by-invite-link/<token>`
  - 基于邀请链接完成注册
- `POST /api/join-by-invite-code`
  - 基于邀请码完成注册

### 机构邀请管理

- `GET /api/organization/invite`
  - 当前机构 `owner` 读取本机构的有效邀请码与邀请链接
- `POST /api/organization/invite/reset`
  - 当前机构 `owner` 重置邀请码与邀请链接

## 前端设计

### 公开页入口调整

现有“提交注册申请”入口拆成两个清晰入口：

- `申请开通机构`
- `加入已有机构`

不再保留“所有新账号默认加入星润Starain”的文案和提交逻辑。

### 申请开通机构弹窗

字段：

- 机构名称
- 用户名
- 显示名
- 密码
- 确认密码

提交成功后提示：

- 申请已提交，等待 `Kayn` 审批

### 加入已有机构弹窗

支持两种进入方式：

- 手动输入邀请码
- 从邀请链接打开时自动识别机构

界面行为：

- 已识别机构时展示机构名称与注册链接状态
- 用户只需补充用户名、显示名、密码、确认密码
- 若邀请码或邀请链接失效，直接提示需要联系机构管理员获取新的入口

### 后台管理调整

新增两个管理区域：

- `Kayn` 侧：机构申请审批列表
- 机构 `owner` 侧：机构邀请设置

机构邀请设置至少展示：

- 当前邀请码
- 当前邀请链接
- 重置按钮

现有“账号审批”页保留，但文案与定位需要调整，避免继续暗示“普通成员统一由全局审批加入星润”。

## 错误处理

- 机构名称已存在：返回 `409`
- 同名机构申请已在待审：返回 `409`
- 用户名已存在：返回 `409`
- 邀请码无效或已失效：返回 `404` 或 `409`
- 邀请链接 token 无效或已失效：返回 `404` 或 `409`
- 非 `super_owner` 调用机构审批接口：返回 `403`
- 非机构 `owner` 调用邀请读取或重置接口：返回 `403`
- 已处理申请重复审批：返回 `409`

## 测试策略

后端优先补充自动化测试：

- 机构申请提交成功
- 重复机构名申请被拒绝
- `Kayn` 审批后自动创建机构、首个 `owner`、唯一 `active` 邀请
- 非 `Kayn` 无法审批机构申请
- 邀请码加入机构成功
- 邀请链接加入机构成功
- 重置邀请后，旧邀请码和旧 token 立即失效
- 重置邀请后，新邀请码和新 token 可用
- 非机构 `owner` 无法重置邀请

前端补充交互测试：

- 公开页展示两个入口
- 旧的“默认加入星润Starain”注册文案被移除
- 邀请链接打开后能正确展示目标机构
- 邀请失效时显示错误提示
- 机构 `owner` 重置后页面展示新的邀请码和邀请链接

## 本次明确不做

- 一个机构多个同时有效的邀请码或邀请链接
- 邀请入口过期时间配置
- 机构 owner 审批成员加入
- 邮件/短信邀请通知
- 机构间切换登录态
- 更细粒度的机构角色体系

## 成功标准

- 新机构可以通过申请审批完成开通
- 审批通过后，机构申请人自动获得该机构 `owner` 身份
- 机构成员能通过邀请码或邀请链接直接加入正确机构
- 每个机构始终只有一个有效邀请入口
- 重置邀请后旧入口立即失效
- 系统中不再存在“所有注册默认归属星润Starain”的公开注册逻辑
