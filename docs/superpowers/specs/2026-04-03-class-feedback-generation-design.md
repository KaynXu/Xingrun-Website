# Class Feedback Generation Design

## Goal

新增一个独立的“班级反馈生成”页面，支持老师按任意时间范围为某个班级生成阶段反馈，而不是固定按 7 天一轮。系统需要汇总该时间范围内的课次记录、课后反馈、老师本次补充备注，以及历史上已经确认过的阶段反馈，最终生成：

- 一篇可直接发给家长群的班级总评
- 每位学生一段可直接发给家长的个性化反馈

生成后老师可以逐个编辑、自动保存、统一复制。只有老师最终确认后的内容才会进入后续 AI 积累，AI 初稿不进入长期记忆。

## Confirmed Scope

- 功能入口为独立新页面，页面名称为“班级反馈生成”。
- 老师必须选择 `class_id + start_date + end_date`，系统按该时间范围汇总资料。
- 页面生成结果包含两层：
  - 班级总评
  - 每位学生的个性化反馈
- 老师在生成前可以补充半结构化阶段备注，包括：
  - 班级整体状态
  - 家长共性反馈
  - 本阶段教学重点或考试节点
  - 下阶段教学预告及与本阶段的承接关系
  - 按学生勾选的“阶段变化”标签与补充说明
- 学生“阶段变化”标签默认提供一套系统内置选项，老师可在该基础上自定义新增、停用、调整顺序。
- 老师生成后可逐个编辑、自动保存、单条复制、统一复制。
- 只有老师最终确认后的班级总评与学生反馈才进入 AI 的长期积累。
- “进步明显 / 有点回落 / 变化不大”等对比型判断必须参考该学生上一条已确认反馈，并优先寻找同粒度基线。

## Existing Context

- 当前仓库已经有老师反馈工作台能力，包含前后端存储、生成草稿、自动保存、复制全部等基础链路。
- 已有 `TeacherFeedbackWorkspace` 与相关 API 更偏向“单节课 / 课后反馈”场景，而本需求是向上抽象成“班级阶段反馈”。
- 当前讨论中已经确认：这个能力不应绑定“每周一次”，因为假期存在按天发送班级测评的场景。
- 当前系统已经沉淀了课次记录、课后反馈等素材，适合作为“班级反馈生成”的基础数据源。

## Recommended Approach

采用“独立页面 + 分步式生成向导 + 最终确认版进入长期积累”的方案。

### Why This Approach

- 独立页面比在现有复习生成/老师反馈工作台里继续叠模式更清晰，避免单节课反馈与阶段反馈混在一起。
- 分步式向导能显式展示“本次生成到底读了哪些资料”，符合“AI 不是在猜，而是在读资料”的产品定位。
- 将“草稿保存”与“最终确认”分开，可以既保证老师编辑过程不丢，又防止未确认草稿污染未来 AI 积累。

## Product Framing

### Core Product Promise

这个功能不是再做一个 AI 写作页，而是做一个“班级反馈生成”与“长期教学记忆”闭环：

1. 平时的课次记录、课后反馈持续沉淀为原始素材。
2. 老师在某个时间范围内补充阶段备注。
3. AI 读取素材生成班级总评与个性化反馈。
4. 老师编辑并最终确认。
5. 最终确认版反过来成为后续 AI 的高质量记忆素材。

### Output Positioning

- 班级总评：偏群发成品文案，可直接发送给家长群。
- 学生个性化反馈：偏单个家长成品文案，可直接发送，不要求老师再二次重写。

## User Flow

### 1. Select Scope

老师进入“班级反馈生成”页面后，先完成以下输入：

- 选择班级
- 选择开始日期
- 选择结束日期

提交后系统开始汇总该时间范围内的素材。

### 2. Review Source Summary

系统展示本次已汇总到的资料摘要，重点是建立老师对数据来源的信任，而不是要求老师重读所有原文。建议展示：

- 命中的课次记录数量
- 命中的课后反馈数量
- 班级内学生覆盖情况
- 素材偏少的学生名单
- 已命中的历史阶段反馈摘要

必要时允许老师展开查看某条原始记录，但默认以摘要为主。

### 3. Add Stage Notes

老师补充本次阶段备注。这里不用一块大文本，而采用“结构化选项为主，短文本补充为辅”的半结构化表单。

### 4. Generate Drafts

系统基于汇总素材与阶段备注生成：

- 班级总评草稿
- 每位学生的反馈草稿

### 5. Edit And Confirm

老师进入编辑工作区，逐个调整文案。编辑完成后点击“确认本次反馈”，系统将当前最终版本标记为正式阶段反馈，并进入长期积累。

## Stage Notes Design

### Class-Level Notes

老师补充以下班级级别信息：

- 本阶段班级整体状态
- 最近家长群共性反馈
- 本阶段教学重点或考试节点
- 下阶段教学预告，以及与当前阶段内容的承接关系

每项支持：

- 默认标签或快捷短语
- 一段简短自由补充

### Student Highlights

老师可以对若干学生补充“本阶段特别变化”。交互建议为：

1. 选择学生
2. 为该学生勾选 1-3 个变化标签
3. 可选补一句具体说明

### Default Label Groups

系统内置默认标签分组如下，老师可以基于此自定义：

- `课堂状态`
  - 进入状态快
  - 注意力更集中
  - 注意力波动
  - 开口更主动
  - 开口偏少
- `学习表现`
  - 基础更稳
  - 知识点仍卡住
  - 纠错后保持更好
  - 完整表达有进步
  - 应用时还不稳定
- `课后执行`
  - 作业完成更稳
  - 作业拖延
  - 复习配合度提升
  - 家长跟进较积极
  - 家庭练习不足
- `阶段变化`
  - 进步明显
  - 有点回落
  - 变化不大
  - 情绪更稳定
  - 需要下阶段重点关注

## Output Design

### Class Summary

班级总评是一段可直接发群的成品文案，建议隐含覆盖以下内容：

- 本阶段整体学习内容
- 班级共性状态
- 共性进步
- 共性提醒
- 下阶段预告

页面上不必拆成小标题，但模型生成时应覆盖这些要素。

### Student Entry

每位学生反馈是一段可直接发给单个家长的成品文案，建议隐含覆盖以下四个要素：

1. 这段时间学了什么
2. 这个学生具体表现在哪里
3. 当前最值得关注的一个点
4. 下阶段会怎么继续带

页面上同样不要求显式小标题，目标是让文案自然、不模板化，但判断依据清晰。

## Editing Workspace

### Layout

生成后的页面采用上下结构：

- 上半区：班级总评
- 下半区：学生反馈列表

这样更符合老师实际查看与发送顺序。

### Student Card

每位学生一张卡片，建议包含：

- 学生姓名
- 本次引用素材摘要，例如“2 节课次记录 + 1 条阶段备注”
- 反馈正文编辑框
- 当前状态：
  - `AI 初稿`
  - `已修改未保存`
  - `已保存`
  - `已检查`
- 单条复制按钮
- 标记已检查按钮

### Save Behavior

- 生成完成后先落一版草稿。
- 老师编辑时自动保存。
- 失焦时再触发一次兜底保存。
- 离开页面前若存在未保存变更，给予提醒。
- 只有点击“确认本次反馈”后，当前 `final_text` 才能进入长期积累。

### Copy Actions

第一版建议至少提供：

- `复制班级总评`
- `复制全部学生反馈`

“复制全部学生反馈”的输出格式建议为：

```text
张三：
（反馈正文）

李四：
（反馈正文）
```

后续如确有需要，再补“复制全部（班级总评 + 学生反馈）”。

## Data Model

命名不使用 `weekly_*`，统一采用更通用的 `class_feedback_*`。

### `class_feedback_task`

表示一次班级反馈生成工作，建议包含：

- `id`
- `class_id`
- `start_date`
- `end_date`
- `period_length_days`
- `period_granularity`
- `status`
  - `draft`
  - `confirmed`
- `created_by`
- `created_at`
- `confirmed_at`

### `class_feedback_note`

保存班级级别阶段备注，建议包含：

- `task_id`
- `class_status_tags`
- `class_status_note`
- `parent_feedback_note`
- `teaching_focus_note`
- `next_stage_preview_note`

### `class_feedback_student_highlight`

保存老师为单个学生补充的阶段变化，建议包含：

- `task_id`
- `student_id`
- `selected_labels`
- `note`

### `class_feedback_class_summary`

保存班级总评文本，建议包含：

- `task_id`
- `ai_draft`
- `final_text`
- `last_saved_at`

### `class_feedback_student_entry`

保存每位学生的阶段反馈，建议包含：

- `task_id`
- `student_id`
- `ai_draft`
- `final_text`
- `last_saved_at`
- `checked_at`

### `class_feedback_source_link`

记录本次生成引用了哪些原始素材，便于解释与追溯。建议包含：

- `task_id`
- `source_type`
  - `lesson`
  - `teacher_feedback`
  - `confirmed_class_feedback`
- `source_id`
- `student_id`（可空；班级级素材可不绑定学生）

### `class_feedback_label_config`

保存老师自定义的学生变化标签配置，建议包含：

- `owner_user_id`
- `label_group`
- `label_text`
- `sort_order`
- `is_active`
- `is_system_default`

## Period Granularity Rules

系统需要为每次已确认反馈记录一个可比较的粒度，服务于后续“阶段变化”判断。第一版建议使用以下规则：

- 若 `start_date == end_date`，则 `period_granularity = daily`
- 若 `period_length_days` 在 6 到 8 天之间，则 `period_granularity = weekly`
- 其他情况记为 `custom`

这样平时按周发、假期按天发、特殊阶段自定义时间范围都可以被统一表达。

## AI Context Rules

### Source Priority

生成当前反馈时，AI 的上下文读取顺序建议为：

1. 当前时间范围内的课次记录
2. 当前时间范围内的课后反馈
3. 老师这次填写的阶段备注与学生变化标签
4. 过去已确认的班级阶段反馈

### Memory Rule

只有老师最终确认后的内容进入长期积累：

- `class_feedback_class_summary.final_text`
- `class_feedback_student_entry.final_text`

以下内容不进入长期记忆：

- AI 初稿
- 未确认草稿
- 中间编辑过程的临时版本

### Comparative Language Rule

模型在使用以下类型表达时，必须先做历史基线比对：

- 进步明显
- 有点回落
- 变化不大
- 比之前更稳定
- 比上次更主动

如果没有可靠基线，不得输出过强的对比性判断，应退化为更保守的客观描述。

## Baseline Lookup Rules

当老师勾选或系统准备生成“阶段变化”类判断时，必须先为该学生寻找上一条已确认反馈作为比较基线，查找规则如下：

1. 先找同一班级下、同一学生、粒度相同的上一条已确认反馈。
2. 如果找不到同粒度记录，再退化成同一班级下最近一条已确认反馈。
3. 如果仍找不到，则禁止生成强比较结论，仅描述当前阶段表现。

### Examples

- 当前为单日反馈时，优先对比上一条 `daily` 已确认反馈。
- 当前为接近周反馈的 7 天区间时，优先对比上一条 `weekly` 已确认反馈。
- 当前为特殊 12 天区间时，可优先对比上一条 `custom` 已确认反馈；若没有，再退化为最近一条已确认反馈。

## Generation Rules

1. 老师选择班级和时间范围。
2. 系统汇总该时间范围内的课次记录、课后反馈与班级学生名单。
3. 系统拉取该班历史上已确认的阶段反馈。
4. 老师补充阶段备注与学生变化。
5. 系统先生成班级总评草稿。
6. 系统再逐个生成学生反馈草稿。
7. 老师进入编辑工作区，逐个修订。
8. 点击“确认本次反馈”后，当前最终版本进入长期积累。

## Error Handling

- 所选时间范围内没有任何可用课次记录：
  - 阻止直接生成，提示老师调整时间范围或补录资料。
- 某些学生素材明显偏少：
  - 允许生成，但在页面上显式提示“资料较少”，模型文案必须避免编造细节。
- 学生在所选时间范围中途加入或移出班级：
  - 只按该时间范围内实际命中的素材参与生成。
- 重新生成：
  - 允许覆盖 AI 草稿。
  - 不自动覆盖老师已经确认过的最终稿，除非老师主动重新确认。
- 班级总评已经修改但学生反馈尚未全部检查：
  - 允许分阶段保存，但最终确认动作仍以整份反馈为单位。

## Testing Strategy

### Backend Tests

- 新增 `class_feedback_*` 数据对象的持久化测试。
- 新增按 `class_id + start_date + end_date` 创建与读取任务的测试。
- 新增仅最终确认稿进入历史积累的测试。
- 新增同粒度基线优先、无同粒度时退化到最近一条的查找测试。
- 新增无历史基线时禁止输出强比较型标签/提示的测试。
- 新增素材不足时仍可生成但带提示标识的测试。

### Frontend Tests

- 新增“班级反馈生成”页面的范围选择测试。
- 新增素材摘要区渲染测试。
- 新增阶段备注表单和学生变化标签交互测试。
- 新增生成后逐个编辑、自动保存、标记已检查的测试。
- 新增统一复制格式测试。
- 新增只有点击“确认本次反馈”后才标记为长期积累来源的测试。

## Non-Goals

- 第一版不直接发送给家长。
- 第一版不做自动定时生成。
- 第一版不做跨班级合并反馈。
- 第一版不做复杂图表分析。
- 第一版不把老师标签配置做成重型后台管理系统。
- 第一版不让 AI 初稿自动进入长期积累。

## Risks And Mitigations

- 如果页面只强调“生成”，老师可能感知不到系统读了哪些资料。
  - 处理方式：保留“素材摘要”步骤，先建立信任，再进入生成。
- 如果将比较型文案直接建立在当前素材上，容易出现“进步明显”这类无依据判断。
  - 处理方式：将历史基线匹配写成硬规则，并优先匹配同粒度已确认反馈。
- 如果把周期写死成 weekly，假期按天发送的场景会立刻受限。
  - 处理方式：页面和数据命名统一用 `class_feedback_*`，时间范围始终由老师手选。
- 如果把草稿也作为记忆素材，AI 容易被自己未经确认的说法带偏。
  - 处理方式：只有老师最终确认稿进入长期积累。

## Implementation Notes

- 优先复用现有老师反馈工作台已有的草稿保存、复制、前后端存储思路，减少重复造轮子。
- 命名、路由、数据对象尽量直接使用 `class_feedback_*`，不要在代码层写死 weekly 语义。
- 基线查找逻辑建议提取成独立 helper，避免生成链路里散落多处条件判断。
