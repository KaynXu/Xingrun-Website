# 班级管理负责老师概念统一设计

## 背景

当前班级管理页面已经收敛为“一个班级只绑定一个老师账号”。

但页面文案仍同时出现两套表达：

- `负责老师`
- `班级老师分配`

在现有业务语义下，这两者实际指向同一件事：班级当前绑定的唯一老师账号。继续并列展示会让用户误以为这是两套不同配置，造成理解成本和操作犹豫。

## 目标

将班级管理页面里的老师绑定概念统一为 `负责老师`，让用户在新建和编辑班级时都只面对一个明确模型：

- 每个班级只有一个负责老师
- 负责老师可以查看、选择、替换
- 不再出现与之并列的“班级老师分配”概念
- 班级年级必须通过固定选项选择，不再允许自由文本输入

## 非目标

- 不修改后端接口、字段名或数据结构
- 不改动单老师绑定的实际业务规则
- 不重做当前卡片布局和异步状态逻辑
- 不新增审批、批量分配、多老师协作等能力

## 设计决策

### 方案选择

采用“统一都叫 `负责老师`”的方案。

原因：

- `负责老师` 更符合业务概念，用户更容易理解“一个班只有一个负责人”
- `分配` 更像动作，不适合作为与业务概念并列的模块标题
- 当前真实可编辑入口只有一个老师单选区，保留两个标题会放大重复感

### 新建班级卡片

保留现有老师搜索与单选交互，但整个老师选择区统一命名为 `负责老师`。

文案原则：

- 强调“创建班级时必须选择一个负责老师”
- 明确系统会同步负责老师姓名
- 不再引入“分配”一词

同时，`年级` 字段从自由文本输入改为下拉选择。

固定选项为：

- 一年级
- 二年级
- 三年级
- 四年级
- 五年级
- 六年级
- 初一
- 初二
- 初三
- 高一
- 高二
- 高三

这些选项必须与页面顶部现有年级筛选使用完全相同的一组值，避免“筛选值”和“班级数据值”不一致。

### 已有班级卡片

已有班级卡片中，老师相关信息统一为一套表达：

- 删除表单区里只读展示的 `负责老师` 字段，避免和下方可编辑区块重复
- 将原 `班级老师分配` 区块改名为 `负责老师`
- 区块说明改为“当前负责老师：xxx，可直接更换”这类单一语义表达
- `年级` 字段同样改为固定选项下拉，禁止继续手动输入任意文本

保留现有搜索、单选、更换老师、刷新绑定等交互，不改变交互能力，只消除概念重复。

## 文案规范

页面内统一使用以下表达：

- 模块标题：`负责老师`
- 摘要文案：`当前老师` 或 `当前负责老师`
- 操作文案：`选择为负责老师`、`设为当前负责老师`
- 错误提示：`负责老师保存失败`、`负责老师已保存，但列表刷新失败`

页面内不再出现 `班级老师分配` 这个模块名。

年级相关文案与数据值统一使用上述 12 个固定选项，不再兼容新的自由输入格式。

## 实现边界

本次只做前端信息结构和文案收敛，保持以下内容不变：

- API 调用路径
- `teacher_name` / `teacher_user_id` 字段使用方式
- 单老师绑定的 optimistic update / rollback / refresh guard 逻辑
- 现有单展开卡片结构

允许调整的范围：

- 将班级表单中的 `年级` 输入控件由文本框改为下拉选择
- 复用或抽取现有年级筛选选项，保证新建/编辑与筛选使用同一组选项

## 验收标准

- 新建班级卡片中的老师选择模块标题统一为 `负责老师`
- 已有班级卡片中不再同时出现只读 `负责老师` 字段和可编辑 `班级老师分配` 模块
- 已有班级卡片的老师选择模块统一命名为 `负责老师`
- 页面源码与测试中不再把该模块作为独立的“班级老师分配”概念描述
- 新建和编辑班级时，`年级` 字段只能从 12 个固定选项中选择
- 班级表单使用的年级选项与顶部筛选项完全一致
- 不引入后端接口改动，不影响当前单老师绑定行为
