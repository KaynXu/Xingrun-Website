# 账号审批与后台访问设计

## 背景

当前系统只有一个固定 `admin` 账号，登录成功后即可进入后台。项目需要升级为更接近 SaaS 的账号体系，但本阶段仅支持单机构 `星润Starain`。

本次目标：

- 将现有 `admin` 升级为最高权限账号，用户名改为 `Kayn`
- 所有用户必须先提交注册申请，经审批通过后才能登录后台
- 所有账号必须归属于机构
- 本阶段只支持一个机构：`星润Starain`
- 仅实现最高权限账号审批注册申请，不实现机构主理人后台

## 方案概览

采用在现有 SQLite 基础上扩展账号与机构模型的方案，不引入外部认证服务。

新增数据实体：

- `organizations`
  - 预置单条记录：`星润Starain`
- `users`
  - 保存正式账号、角色、机构归属、账号状态
- `registration_requests`
  - 保存待审批的注册申请
- `auth_sessions`
  - 保存登录 token 与对应用户，替代当前写入 `config.json` 的 `_tokens`

## 角色与状态

角色：

- `owner`
  - 最高权限账号，仅 `Kayn`
- `member`
  - 普通后台用户

账号状态：

- `active`
  - 已审批，可登录
- `disabled`
  - 预留，当前界面不开放管理

申请状态：

- `pending`
  - 待审批
- `approved`
  - 已通过，并已创建正式账号
- `rejected`
  - 已拒绝

## 核心流程

### 1. 初始化与迁移

应用启动时执行数据库迁移与种子逻辑：

- 确保 `organizations / users / registration_requests / auth_sessions` 存在
- 确保机构 `星润Starain` 存在
- 读取现有运行配置中的 `admin_username / admin_password_hash`
- 自动创建或更新最高权限账号：
  - 用户名强制设为 `Kayn`
  - 显示名设为 `Kayn`
  - 角色设为 `owner`
  - 状态设为 `active`
  - 机构设为 `星润Starain`
- 若旧配置中存在 `admin` 账号密码哈希，则迁移给 `Kayn`
- 历史配置 token 不再作为主会话来源

### 2. 注册申请

未登录用户可以提交注册申请：

- 输入用户名
- 输入显示名
- 输入密码与确认密码
- 机构固定为 `星润Starain`

提交后：

- 若用户名已被正式账号使用，返回冲突错误
- 若用户名已有待审批申请，返回重复申请错误
- 创建一条 `pending` 申请
- 前端展示“已提交，等待审批”

### 3. 审批

只有 `owner` 可查看待审批列表并执行：

- 通过
  - 创建 `member` 正式账号
  - 写入所属机构 `星润Starain`
  - 申请状态改为 `approved`
- 拒绝
  - 申请状态改为 `rejected`

### 4. 登录与后台访问

登录仅允许正式账号：

- 用户必须存在于 `users`
- 状态必须为 `active`
- 密码校验通过

登录成功后：

- 创建 `auth_sessions` 记录
- 前端拿到 token
- 后续后台 API 通过 token 解析当前用户

访问控制：

- 未登录用户只能停留在首页、登录、注册申请
- 没有正式账号的申请人无法进入后台
- 审批管理接口仅 `owner` 可访问

## 前端设计

保持现有黑色科技感与圆角卡片风格，不扩展无关页面。

### 首页

- 登录入口保留
- 增加“注册申请”入口

### 登录弹窗

- 保持当前视觉风格
- 文案改为正式账号登录
- 若账号不存在或未审批，通过后端统一返回清晰错误

### 注册申请弹窗

字段：

- 用户名
- 显示名
- 密码
- 确认密码
- 机构（固定展示 `星润Starain`）

反馈：

- 成功提交提示
- 重复申请 / 用户名冲突 / 密码不一致错误提示

### 后台管理页

新增一个只服务本需求的账号管理页：

- 显示当前账号卡片：`Kayn / 最高权限账号 / 星润Starain`
- 显示待审批申请列表
- 每条申请支持“通过 / 拒绝”

不做用户搜索、禁用账号、机构切换、多机构配置等额外功能。

## API 设计

新增或调整接口：

- `POST /api/register-request`
  - 提交注册申请
- `POST /api/login`
  - 改为数据库用户登录
- `GET /api/me`
  - 返回当前登录用户信息
- `GET /api/admin/registration-requests`
  - 获取待审批申请列表
- `POST /api/admin/registration-requests/<id>/approve`
  - 审批通过
- `POST /api/admin/registration-requests/<id>/reject`
  - 审批拒绝

现有受保护接口统一改为依赖数据库会话鉴权。

## 错误处理

- 用户名已存在：返回 409
- 申请已存在：返回 409
- 用户未审批或不存在：登录返回 401，并给出明确提示
- 非 `owner` 调用审批接口：返回 403
- 申请不存在或已处理：返回 404 或 409

## 测试与验证

至少验证以下路径：

- `Kayn` 可正常登录后台
- 未注册用户不能进入后台
- 新用户可提交申请
- `Kayn` 可在后台看到申请并通过
- 审批后新用户可登录
- 拒绝后申请不会生成正式账号
- 现有课程、题库、设置功能在登录后仍可正常访问

## 本次明确不做

- 多机构创建与切换
- 机构主理人添加成员
- 找回密码
- 邮件通知
- 用户资料编辑
- 细粒度权限系统
