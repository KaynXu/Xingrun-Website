# Consultation Remarks List Design

## Goal

在 `咨询记录` 页面把现有 `follow_up_note` 直接展示到列表中，同时保持桌面端表格行高统一、移动端卡片视觉整齐，不引入横向滚动、悬浮展开或额外详情交互。

## Scope

本期包含：

- 桌面端咨询记录表格新增备注展示
- 移动端咨询记录卡片同步展示备注
- 统一调整列表项高度预算，避免不同备注长度导致列表节奏不一致

本期不包含：

- 新增或修改后端接口
- 修改咨询记录录入、编辑、搜索、保存逻辑
- 新增备注展开、tooltip、横向滚动或单独详情列
- 为备注增加新的字数限制规则

## Current Context

当前 `ConsultationPage` 已同时维护两套列表展示：

- `2xl` 以上使用桌面端表格
- `2xl` 以下使用移动端卡片

咨询记录数据结构里已经有 `follow_up_note`，只是当前列表未显示。桌面端现有“咨询科目 / 来源渠道”这一列本身就是双行信息列，最适合承接备注，不需要再额外增加新列。

## Product Decision

### 1. 备注并入“咨询科目 / 来源渠道”列

桌面端不新增“备注”列，直接把备注并入现有“咨询科目 / 来源渠道”单元格。

采用这个方案的原因：

- 不增加表格总宽度
- 不破坏现有列结构和扫描路径
- 备注与科目、来源同属咨询背景信息，放在同一块语义最顺

### 2. 每行统一抬高到三层信息预算

桌面端每一行统一按三层信息展示：

- 第 1 行：`咨询科目`
- 第 2 行：`来源渠道`；如果有 `source_channel_note`，继续接在这一行
- 第 3 行：`备注：{follow_up_note}`

即使某条记录没有备注，也保持统一行高，不因为是否有备注而让每行高度不同。

### 3. 移动端卡片保持同口径

移动端卡片不新增独立备注模块，备注直接并入现有咨询信息区，顺序与桌面端保持一致：

- 咨询老师
- 咨询科目
- 来源渠道
- 备注

这样桌面端和移动端都遵守同一套信息组织逻辑。

## Display Rules

### 1. 字段展示规则

- `consultation_subject` 为空时，继续显示现有兜底文案 `未填写咨询科目`
- `source_channel` 与 `source_channel_note` 继续复用现有 `getConsultationSourceLabel()` 输出结果
- `follow_up_note` 仅在有值时显示，前缀固定为 `备注：`
- `follow_up_note` 为空时，不补 `—`，只保留统一高度

### 2. 视觉优先级

- 科目保持当前主信息权重
- 来源渠道维持次级说明文字样式
- 备注与来源渠道区分开，但不做高对比强调，避免第三行抢占整表注意力

### 3. 边界假设

本方案默认前提是：真实业务里的备注大多是短句或短语，而不是长段落。

因此这一轮不额外增加：

- 备注折叠
- 展开按钮
- tooltip 预览
- 横向滚动

如果后续实际数据证明备注明显变长，再单独讨论新的信息密度方案，不在这一轮提前加复杂交互。

## Implementation Outline

### 1. 桌面端表格

在 `frontend/src/App.tsx` 的 `ConsultationPage` 桌面端表格中：

- 保持现有表头不变
- 在“咨询科目 / 来源渠道”单元格下追加备注行
- 调整该单元格与整行的垂直留白，使三层信息在所有记录中看起来是固定节奏

### 2. 移动端卡片

在同一文件的移动端卡片布局中：

- 在当前咨询信息区域追加备注一行
- 不新增新的卡片块或分组容器
- 让所有卡片的主体信息区保留一致的垂直节奏

### 3. Data Flow

本次直接消费现有 `ConsultationRecord.follow_up_note`。

不新增状态、不改接口、不新增派生字段。列表加载、搜索、编辑保存完成后的刷新逻辑全部保持现状。

## Error Handling

本次不新增独立错误流。

如果某条记录备注为空，列表按“无备注但保留统一高度”显示；如果备注有值，直接跟随现有列表渲染链路显示。

## Testing

本期至少补一组前端源码级断言，确认：

- 桌面端列表源码包含 `follow_up_note` 展示
- 备注展示位于现有“咨询科目 / 来源渠道”信息块中，而不是新增独立列
- 移动端卡片源码也包含备注展示

如果后续进入实现，再根据现有测试习惯决定是否补充交互级渲染测试。

## Risks

- 这个方案依赖“备注通常不长”这一前提；如果后续录入内容明显变长，三层信息预算会重新吃紧
- 桌面端和移动端都在 `frontend/src/App.tsx`，实现时需要同步修改两套布局，避免只改一侧
- 如果样式只抬高了有备注的记录而没有统一抬高全部记录，就会回到用户不接受的“每张卡片大小不一样”问题
