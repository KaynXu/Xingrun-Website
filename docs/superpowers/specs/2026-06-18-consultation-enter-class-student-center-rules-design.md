# 咨询进班接轨学管中心班级规则设计

## 背景

咨询记录在选择 `成功进班` 后，会打开 `进班与学员档案` 弹窗。弹窗里已有三个选项：

- `已有班级`
- `快速建班`
- `转化待进班`

本次只调整前两个选项。目标是让咨询进班使用学管中心班级管理的筛选、排序、建班规则，同时保持咨询弹窗轻量，不把学管中心完整大弹窗搬进来。

## 范围

### 本次要做

1. `已有班级` 接入学管中心班级筛选逻辑。
2. `快速建班` 接入学管中心创建班级的规则和生成逻辑。
3. 保持当前进班弹窗的三卡片结构与紧凑风格。
4. 为已有班级筛选、快速建班 payload、成功进班闭环补测试。

### 本次不做

1. 不调整 `转化待进班`。
2. 不调整咨询流程图蓝绿灯规则。
3. 不调整 Over 成功/失败逻辑。
4. 不搬运学管中心完整班级编辑弹窗 UI。
5. 不改学管中心自身的班级管理规则。

## 已有班级

`已有班级` 区域使用和学管中心班级管理一致的班级筛选思路：

- 科目
- 教师
- 学段
- 年级
- 班型或小课/班课类型

默认推荐值来自当前咨询记录：

- 咨询科目推荐到科目筛选，但不锁死，可以手动改。
- 带课教师或已选择的进班教师推荐到教师筛选，但不锁死，可以手动改。
- 咨询年级只作为推荐，不锁死，因为学生可能从六年级咨询进入七年级或八年级班。

筛选结果仍放在下拉框中，不改成列表。下拉框中的班级排序沿用学管中心班级管理排序：

- 小课优先
- 班课靠后
- 同类型内低年级到高年级

选择已有班级后，确认进班沿用当前 `/api/consultations/<id>/enter-class` 闭环，写入 `success_class_id`，并完成成功进班。

## 快速建班

`快速建班` 的底层规则接轨学管中心创建班级逻辑：

- 使用学管中心的空班级草稿结构作为基础。
- 使用学管中心的班级保存 payload 生成规则。
- 生成班名和结构化字段时，遵循学管中心当前班级命名规则。
- 带课教师选择后，应绑定到新建班级的负责教师。

UI 不直接复用学管中心完整编辑弹窗，而是在咨询进班弹窗里保留紧凑建班区。建班区至少包含：

- 科目
- 学段
- 年级
- 班型
- 班号或小课名
- 带课教师
- 衔接班

确认后先创建班级，再把咨询进班到新建班级。创建成功后，新班级应能在学管中心班级管理中找到。

## 共享边界

为了避免咨询弹窗和学管中心各写一套规则，本次应增加或整理一个小的规则适配层。

这个适配层负责：

- 将咨询记录转换为班级筛选默认值。
- 将咨询快速建班草稿转换为学管中心班级表单草稿。
- 调用学管中心已有的班级 payload 构建逻辑。
- 复用班级排序与筛选规则。

咨询组件只负责 UI 和用户操作，不直接复制学管中心复杂规则。

## 错误处理

- 已有班级未选择时，确认按钮保持不可提交或显示明确提示。
- 快速建班缺少必要字段时，使用学管中心一致的校验文案。
- 快速建班创建失败时，错误显示在进班弹窗内，不关闭弹窗。
- 进班接口失败时，保持弹窗打开，避免老师重新填写。

## 测试

至少补以下测试：

1. 已有班级筛选使用推荐科目/教师/年级，但这些推荐值可被修改。
2. 已有班级下拉结果使用学管中心排序。
3. 快速建班 payload 由学管中心班级保存规则生成。
4. 快速建班成功后会进入成功进班闭环。
5. 快速建班创建出来的班级可在 `/api/classes` 或学管中心班级列表中找到。

## 验收标准

1. 咨询页面成功进班弹窗仍显示 `已有班级 / 快速建班 / 转化待进班` 三卡片。
2. `已有班级` 能通过筛选条件缩小班级下拉结果。
3. 筛选默认推荐能帮老师少选，但老师可以手动调整。
4. `快速建班` 创建出的班级命名、字段、负责教师绑定与学管中心规则一致。
5. 创建新班后，咨询记录自动完成成功进班。
6. 本地预览中无白屏、无前端 console error。
