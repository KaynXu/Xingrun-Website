# 小程序家长端双分区设计

## 目标

把家长小程序主体验收束为两个底部 Tab：

- 我的：管理家长绑定的孩子，并新增绑定孩子。
- 拍照上传：给当前选中的孩子拍照或选图上传错题。

本轮只调整家长端小程序前端的信息架构和入口关系，不改上传 API、错题识别、错题本 PDF、绑定 API 或后台任务语义。

## 页面结构

`app.json` 增加底部 `tabBar`，只放两个主入口：

- `pages/parent-home/index`，文案为“我的”。
- `pages/parent-upload/index`，文案为“拍照上传”。

现有 `pages/index/index` 继续作为启动跳转页，保留 `parent-bind` 和 `parent-wrongbook` 为普通子页面。

## 我的

`parent-home` 从“孩子错题与上传入口”调整为“我的孩子”。它负责：

- 展示已绑定孩子列表。
- 设置当前上传孩子。
- 进入“绑定更多孩子”。
- 保留每个孩子的“查看错题本”次级入口。

孩子卡片不再把“上传错题”作为主操作。上传行为统一从底部“拍照上传”Tab 进入。

## 拍照上传

`parent-upload` 支持不带 `bindingId` 直接作为 Tab 打开：

- 如果 URL 带 `bindingId`，沿用该孩子。
- 如果本地或服务端只有 1 个绑定孩子，自动选中。
- 如果有多个绑定孩子，页面顶部展示孩子选择区，家长先选一个孩子再上传。
- 如果没有绑定孩子，展示空态，引导去“我的”绑定孩子。

选中孩子后，现有拍照、选图、手动框题、补充错因和统一提交流程保持不变。

## 数据流

- `parent-home` 保存当前上传孩子到本地 storage，并同步到 `app.globalData`。
- `parent-upload` 加载家长 session 和绑定列表后，按 URL 参数、本地当前孩子、单孩子默认的优先级决定当前 `binding`。
- 已接收上传任务的恢复 key 继续按 `openId + bindingId` 隔离，避免切换孩子后混淆进度。

## 状态和错误

- 没有绑定孩子：`parent-upload` 显示去“我的”绑定孩子的操作，不展示上传工具流。
- 多个孩子未选择：显示选择孩子区，不展示上传工具流。
- 已选孩子：展示原有上传工具流。
- 绑定列表加载失败：沿用现有错误卡样式，并允许重新进入页面重试。

## 验证

- 新增或更新小程序页面测试，锁定 tabBar、首页“我的”语义、上传页无 `bindingId` 时的孩子选择行为。
- 继续运行小程序视觉 guardrail 和上传稳定性 proof。
- 最终 proof 使用临时脚本串起定向测试、guardrail 和 `git diff --check`。
