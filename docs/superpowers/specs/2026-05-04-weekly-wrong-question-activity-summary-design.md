# 超级管理员本周错题活跃数据总结设计

日期：2026-05-04

## 背景

智能错题已经能按班级、学生和老师视角查看错题记录。超级管理员还需要一个更高层的本周活跃数据入口，用来快速知道哪些班级、老师、学生最近使用得多，而不是逐个进入班级或学生错题本查看。

这一版只聚焦“活跃情况列举”。页面不强调竞赛式排名，也不做复杂运营报表。数据按数量从多到少排列，帮助超级管理员自然扫出本周最活跃的班级、老师和学生。

## 用户目标

超级管理员打开智能错题后，能快速回答三个问题：

- 本周哪些班级新增错题最多？
- 本周哪些老师负责的班级最活跃，还有多少待跟进？
- 本周哪些学生新增错题明显，当前错题本累计到多少题，主要集中在哪些专题？

## 入口与权限

在网页后台 `智能错题` 页面内新增一个入口，名称为 `本周数据总结`。

入口只对 `super_owner` 可见。`owner`、`admin`、`member` 不显示该入口，也不能直接访问对应接口数据。

默认统计当前自然周。页面允许切换上一周或指定周次。超级管理员可以查看全平台数据，也可以按机构筛选后查看某个机构内的数据。

## 方案选择

### 方案 A：极简三列表

只展示本周活跃班级、活跃老师、活跃学生三块列表。

优点是实现最快，信息直接。缺点是后续想看某个机构时需要再加筛选。

### 方案 B：三列表加周次和机构筛选

展示三块列表，同时支持切换周次和机构筛选。默认全平台，选择机构后只看该机构数据。

优点是既保持简单，又符合超级管理员跨机构查看的真实需求。缺点是后端需要多处理一个机构筛选条件。

### 方案 C：三列表加 AI 总结

在方案 B 基础上增加一段 AI 本周总结。

优点是读起来更像周报。缺点是第一版会增加生成、缓存和失败处理成本，而且用户当前主要需要列举数据。

### 推荐

第一版采用方案 B：三列表加周次和机构筛选。暂不做 AI 总结，不做图表，不做自动导出。

## 页面内容

页面由三个主要区域组成：

- 本周活跃班级
- 本周活跃老师
- 本周活跃学生

每个区域默认显示前 10 条，按核心数量从多到少排列。标题和行文避免使用“第 1 名”“榜首”等强排名表达，只做自然列举。

如果没有数据，展示空态：`本周暂无错题活跃数据`。

## 活跃班级

活跃班级按本周新增错题数从多到少排列。

每行显示：

- 班级名称
- 所属机构
- 本周新增错题数
- 上传学生数
- 最近上传时间

示例：

```text
五年级3班：18 道，6 名学生上传，最近上传 今天 18:32
六年级2班：13 道，4 名学生上传，最近上传 昨天 21:10
四年级1班：9 道，3 名学生上传，最近上传 周三 19:45
```

排序规则：

1. 本周新增错题数多的在前。
2. 数量相同，上传学生数多的在前。
3. 仍相同，最近上传时间新的在前。

## 活跃老师

活跃老师按其负责班级下本周新增错题数从多到少排列。

每行显示：

- 老师姓名
- 所属机构
- 负责班级数量
- 负责班级下本周新增错题数
- 涉及学生数
- 待跟进数量

示例：

```text
王老师：负责班级本周新增 31 道，涉及 12 名学生，待跟进 5 条
李老师：负责班级本周新增 22 道，涉及 8 名学生，待跟进 3 条
```

待跟进数量第一版使用智能错题现有状态语义计算：未掌握、未归档或仍需要老师处理的本地微信错题记录计入待跟进。具体实现时应复用现有智能错题筛选口径，避免同一条记录在页面上口径不一致。

排序规则：

1. 本周新增错题数多的在前。
2. 数量相同，涉及学生数多的在前。
3. 仍相同，待跟进数量多的在前。

## 活跃学生

活跃学生按本周新增错题数从多到少排列。

每行显示：

- 学生姓名
- 所属班级
- 所属机构
- 本周新增错题数
- 当前错题本总题数
- 主要专题

示例：

```text
王睿博｜七年级5班：本周新增 7 道，错题本共 24 道，主要专题：几何、计算
毛裕宁｜七年级5班：本周新增 5 道，错题本共 18 道，主要专题：应用题
```

主要专题取本周新增错题里数量最多的 1 到 3 个专题。没有专题时显示 `未分类`。

排序规则：

1. 本周新增错题数多的在前。
2. 数量相同，当前错题本总题数多的在前。
3. 仍相同，最近上传时间新的在前。

## 数据口径

本周默认按自然周计算，周一 00:00:00 到周日 23:59:59。日期使用服务器本地时间。

计入统计的记录：

- 来源为微信小程序家长上传或现有智能错题本地记录。
- 记录属于当前查询周。
- 记录未被硬删除。

不计入统计的记录：

- 已硬删除的错题。
- 不属于当前查询周的历史错题。
- 无法归属到机构、班级或学生的数据。后续可单独进入异常数据治理，不混入本周活跃总结。

当前错题本总题数按学生现有有效错题记录计算，不限定本周。

## API 设计

新增一个超级管理员专用接口：

```text
GET /api/admin/wrong-question-activity-summary?week_start=YYYY-MM-DD&organization_id=
```

返回结构建议：

```json
{
  "week_start": "2026-05-04",
  "week_end": "2026-05-10",
  "class_items": [],
  "teacher_items": [],
  "student_items": []
}
```

`organization_id` 可选。不传时返回全平台数据，传入时只返回该机构数据。

第一版不新增写接口，不做 AI 生成缓存。

## 错误处理

- 无权限访问：返回权限错误，不泄露任何统计数据。
- 周次参数非法：返回明确错误，例如 `week_start must be a valid date`。
- 指定机构不存在：返回空数据或 404，具体实现时跟现有管理员机构接口口径保持一致。
- 数据为空：页面展示空态，不报错。

## 验收标准

- `super_owner` 能在智能错题中看到 `本周数据总结` 入口。
- 非 `super_owner` 看不到入口，直接调用接口也不能拿到数据。
- 页面默认展示当前周数据。
- 页面可以按周次切换。
- 页面可以按机构筛选。
- 活跃班级按本周新增错题数从多到少列举，并显示班级、错题数、上传学生数、最近上传时间。
- 活跃老师按负责班级下本周新增错题数从多到少列举，并显示老师、错题数、涉及学生数、待跟进数量。
- 活跃学生按本周新增错题数从多到少列举，并显示学生、班级、错题数、当前错题本总题数、主要专题。
- 页面不显示“第 1 名”“榜首”等强排名文案。
- 第一版不出现 AI 总结、图表、自动推送、导出报表入口。

## 非目标

- 不做 AI 本周总结。
- 不做趋势图。
- 不做 Excel/PDF 导出。
- 不做自动提醒老师。
- 不改变家长小程序上传流程。
- 不改变现有每周错题跟进助手的话术生成流程。
