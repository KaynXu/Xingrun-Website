# Wrong Question Hard Delete Design

## Goal

为网站端 `智能错题` 的本地微信错题记录增加“删除本题”能力，并在删除后同步清理该学生旧错题库 PDF，避免无效 PDF 长期占用磁盘。

同时，这次只负责网站主仓库可控部分。微信端不在本仓库内实现代码，改为提供一段可直接交给下游服务 AI 的实现提示词。

## Scope

本期包含：

- 网站端 `SmartWrongQuestionsPage` 的微信错题详情区新增 `删除本题` 按钮
- 本地 `wechat_mp` 错题记录新增真删除接口
- 删除成功后按学生维度清理旧 PDF，并按剩余有效记录决定是否重建
- 前端删除后自动跳到同学生下一题；没有下一题则收起右侧详情区
- 输出一份微信端 / 下游服务 AI 用的实现提示词草稿

本期不包含：

- downstream 错题记录的删除
- 回收站、恢复删除、批量删除
- 改造整套 PDF 生成策略
- 在本仓库内直接实现微信端代码

## Product Decision

### 1. 删除语义是真删除，不是归档

这次 `删除本题` 的语义是彻底删除本地微信错题记录，而不是写成 `archive_status='archived'`。

原因：

- 用户已经明确要求彻底删除
- 归档仍会保留数据库记录，不符合这次需求
- 当前错题库 PDF 是按学生有效记录重建，真删除更容易保证 PDF 与真实记录一致

### 2. 只删除本地微信错题

按钮只对 `source='wechat_mp'` 的本地记录生效，不给 downstream 记录开放。

原因：

- 本仓库只直接控制本地微信错题的 SQLite 表和 PDF 重建链路
- downstream 记录属于外部服务，接口契约和删除副作用不适合这轮顺手猜测实现

### 3. 权限按“可见即可删”处理

任何当前能在网站工作台里看到这条本地微信错题记录的已登录用户，都允许删除它。

实现上不再使用 `_require_staff()`，改为：

- 先要求用户已登录
- 再读取本地记录
- 用现有 `_can_access_wrong_question_record()` 校验当前用户是否可见
- 可见则允许删除，不可见返回 `404`

这与用户要求的“网站也做，任何看得到的人都能删”一致，同时复用现有可见性边界。

## Backend Design

### 1. 新增删除接口

新增网站后端接口：

- `DELETE /api/wrong-questions/<record_id>`

行为仅处理本地微信错题记录：

- 若记录不存在，返回 `404`
- 若记录存在但当前用户不可见，返回 `404`
- 若记录是 downstream 记录，返回 `404`
- 删除成功返回：
  - `ok: true`
  - `deleted_record_id`
  - `student_id`
  - `next_student_library_pdf_path`
    - 还有剩余有效题时返回新路径
    - 已无剩余题时返回空字符串

### 2. 删除后的 PDF 清理与重建

删除逻辑必须把“旧 PDF 占磁盘”作为一级约束处理。

推荐流程：

1. 读取待删记录，拿到 `student_id`
2. 计算该学生当前固定 PDF 路径
3. 删除数据库中的这条记录
4. 先删除该学生当前已有 PDF 文件
5. 查询该学生剩余的 `source='wechat_mp' AND recognition_status='recognized' AND archive_status='active'` 记录
6. 若仍有记录：
   - 按剩余记录重建同一路径 PDF
   - 将这些剩余记录的 `student_library_pdf_path` 更新为新路径
7. 若已无记录：
   - 不重建 PDF
   - 将该学生相关记录上的 `student_library_pdf_path` 清空

关键约束：

- 必须先删旧 PDF，再考虑是否重建，避免磁盘残留
- 不能只删除数据库记录而保留旧 PDF 文件
- 不能在“最后一题删除后”继续留下孤儿 PDF

### 3. 数据层

在 `lesson_manager.py` 增加最小新能力：

- 删除单条本地微信错题记录的 helper
- 按学生批量更新 `student_library_pdf_path` 的 helper
- 按学生清空 `student_library_pdf_path` 的 helper

保持最小侵入：

- 不重命名现有字段
- 不改现有 PDF 生成函数签名
- 不顺手重构微信错题存储模型

## Frontend Design

### 1. 按钮位置

在网站 `SmartWrongQuestionsPage.tsx` 的微信错题详情卡中新增 `删除本题` 按钮。

按钮只在以下条件下显示：

- 当前选中记录是 `source='wechat_mp'`
- 当前记录来自本地微信错题链路

按钮放在现有微信错题操作区，与 `预览 PDF`、`下载 PDF`、`保存掌握情况` 保持同层级视觉关系，但使用明确的危险态样式。

### 2. 交互行为

点击后先二次确认，再调用删除接口。

确认文案语义需要明确两件事：

- 这条题会被彻底删除
- 该学生错题库 PDF 会同步重建或清空

删除成功后的前端行为：

- 从当前 notebook 记录列表中移除被删题目
- 自动选择同学生的下一题
- 如果没有下一题，则清空 `selectedId`，保留学生 notebook 弹窗和左侧目录
- 关闭本次删除态
- 清掉与该题相关的草稿和错误态

### 3. 失败处理

删除失败时：

- 保留当前选题不动
- 在详情区显示删除失败文案
- 不要误清前端列表

## Testing

### Backend

新增测试覆盖：

- 可见用户可以删除本地微信错题
- 不可见用户删除返回 `404`
- 删除后该题数据库记录消失
- 删除后旧 PDF 文件被删除
- 删除后若学生仍有剩余有效题，会重建 PDF
- 删除最后一题后不会留下 PDF 文件

### Frontend

新增测试覆盖：

- 微信错题详情区出现 `删除本题` 按钮
- 点击删除后会调用正确的 `DELETE /api/wrong-questions/<id>`
- 删除成功后会跳到同学生下一题
- 删除最后一题后会清空右侧详情
- downstream 记录不出现该按钮

## External Mini Program Handoff

本仓库不直接改微信端代码。

网站端实现完成后，需要额外给用户一段下游服务 AI 提示词，要求下游服务：

- 在微信错题详情或错题库页增加 `删除本题`
- 调用网站端新增删除接口或下游自身映射接口
- 删除成功后刷新当前学生错题列表
- 若当前题被删后还有下一题，则自动跳下一题
- 若已无下一题，则返回列表空态
- 删除确认文案必须明确“会同步更新错题库 PDF”

## Risks

- 目前网站工作台是混合数据源；如果前端误把 downstream 记录也展示删除按钮，会造成错误调用
- 删除后切换“下一题”的前端状态处理如果不干净，容易留下脏草稿或错误详情
- 若后端只重建 PDF 不先删旧文件，仍可能留下旧文件占磁盘
- 若删除最后一题时遗漏了“清空 PDF 路径快照”，前端可能继续拿到已失效路径
